# ---- NOT HERE: the script CHAIN, and why ------------------------------------
# The opening is a FOUR-script chain -- data_020890a0 -> data_02088a94 ->
# data_02089af8 -> data_020876d4 -- whose chain arguments and camera waypoints
# are stored as ZERO on disc and written at boot by __sinit_02073e6c (392 byte
# stores, the fields are unaligned). VERIFIED by reading arm9_dec.bin:
# data_020890a0+0x103 and +0x62/+0x66/+0x8a/+0x8e are all 00 00 00 00.
#
# Offering src/__sinit_02073e6c.c pulls in NINETY arm9 romdata symbols -- it
# alone accounted for 273 of the 369 unresolved references in this lane's first
# link -- and those symbols are the script blobs themselves (data_02088a94,
# data_02089af8 and data_020876d4 among them, i.e. the chain targets are not
# hosted at all yet).
#
# THEY CANNOT SIMPLY BE ADDED TO port/tools/romdata.py's list. That list
# BYTE-COPIES, and this file's own history says what that costs on a kuppa
# table: data_020876e4 was removed from it because it held six RELOCATED words,
# so the byte copy handed ProcessKuppaScript six raw DS addresses and it faulted
# walking them; it is hosted with real host pointers in hal/ptr_tables.cpp
# instead. Every one of the ninety needs that relocation check first.
#
# So the chain is a follow-on with a known shape, not a line in this file.
# Without it the opening plays its FIRST script and stops at frame 400.

# ---- THE SCRIPT POINTER PATCHER ------------------------------------------
# The opening is a FOUR-script chain -- data_020890a0 -> data_02088a94 ->
# data_02089af8 -> data_020876d4 -- and the chain arguments and the
# argument-blob pointers are stored as ZERO on disc. __sinit_02073e6c writes
# them at boot, byte by byte because the fields are unaligned, e.g.
#   data_02089af8[0x2cf..0x2d2] = (unsigned)data_020876d4   (the chain to 4)
# On the HOST it writes HOST addresses, which is exactly why it has to RUN
# rather than the pointers being byte-copied.
#
# Its 155-symbol closure was audited individually against config/arm9/relocs.txt
# before any of it was hosted (out/intro-cutscene/reloc_audit.txt): 96 symbols
# are byte-copy clean and went into port/tools/romdata.py; 55 carry a real
# pointer at +4 and are hosted with HOST pointers in hal/intro_script_records.cpp;
# 3 are fader vtables port/hal/fader_wipes.cpp already hosts. Nothing was
# byte-copied on faith -- that is the data_020876e4 crash romdata.py banks.
