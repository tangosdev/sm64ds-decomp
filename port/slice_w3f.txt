#   _ZN13PrincessPeach8BehaviorEv     ROM 0x0212a52c dispatches its ModelAnim's
#       vtable SLOT 3 (`add r0,r0,#0xd4 / ldr r1,[r0] / ldr r1,[r1,#0xc] /
#       blx r1`). The matched TU spells that as a four-virtual shadow calling
#       g3, which is MSVC INDEX 3 -- and hal/cxxname_bridge.cpp fills
#       _ZTV9ModelAnim in MSVC numbering, where ROM slots 0 and 1 fold into
#       MSVC 0 and every later ROM slot N is MSVC N-1. MSVC index 3 is
#       ma2_virtual10, ROM slot 4, which takes a Matrix4x3 reference this call
#       does not pass. ROM slot 3 is ModelAnim::UpdateVerts and it is MSVC
#       index 2. This is the wave-19 collision exactly, and it is why
#       LAKITU_BRO's and the RABBIT's renders are host copies while WALL_SIGN's

#       the same one TOAD's D1 has. The TU declares its own struct Actor /
#       ModelAnim / ShadowModel / MovingCylinderClsn / WithMeshClsn and defines
#       ~PrincessPeach, so MSVC emits ??1PrincessPeach@@UAE@XZ calling four
#       decorated member destructors that exist nowhere in this link. Slot 16
#       is spelled inline in the fill from the ROM D1's own five relocs; see
#       hal/actor_classes_ov085.cpp.
#
#   func_ov085_0212a430               \  the two mwcc pointer-to-member
#   func_ov085_0212a46c               /  dispatchers, the gate-16 case for the
