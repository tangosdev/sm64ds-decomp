# GATE 1 -- func_ov055_021112c4, MirrorLuigi's ENTER DISPATCHER
# ===========================================================================
#
# THE UNIVERSE IS CLOSED, over the same class-derived block gates 1 and 2 of
# lane PMFB7 used: every function symbol in ov055's symbols.txt whose mangled
# name names MirrorLuigi, first to last, is 021111a0..02111860, and that is the
# span one translation unit emits. Every `load` relocation in ov055 landing in
# that block whose word reads the target and whose FOLLOWING word is zero gives
# exactly TWO pairs:
#
#     02111a94  code=021112bc  (the ENTER half, whose whole body is `return 1`)
#     02111a9c  code=02111288  (the TICK half, the mirror of the player)
#
# run 02111a94..02111aa4, SOLID, two distinct code words, and the only two
# references into the run are 02111904 and 02111908 -- __sinit_ov055_021118d4's
# own loads, the class's own sinit, which copies both pairs into the sixteen-
# byte cell at data_ov055_02111b70. Nothing else in ov055 can hand this field an
# address. (runs/link100/out/PMFB8/sweep_g1.txt)
#
# WHAT MAKES THIS ROW DIFFERENT FROM PMFB7's TWENTY-ONE, and why it was left for
# its own gate: ITS ARITY IS ONE. The /FAsc listing under the port's own flags
# (runs/link100/out/PMFB8/emit_g1_out.txt) is
#
#     mov  DWORD PTR [eax+472], ecx     c->pp = p, 472 = 0x1d8
#     mov  edx, DWORD PTR [ecx]         the pair's FIRST word
#     test edx, edx / jne               the null test the ROM also makes
#     mov  ecx, DWORD PTR [ecx+4]       the pair's SECOND word, the adjust
#     push DWORD PTR _a2$[ebp]          ONE stack argument
#     add  ecx, eax                     receiver = this + adjust
#     call edx
#     pop  ebp / ret 0                  the caller does NOT clean up after it
#
# A CALL, not a tail jump, with one pushed word the caller never pops, because
# __thiscall's stack half is callee-popped. So the face is
# __fastcall(self, dead_edx, int) -- lane FWD's MgCup shape -- which takes ecx
# as its receiver and pops the same one word. /Zp4 changes 0 listing lines
# outside the TITLE and is NOT claimed: the member sits at offset 0 of the
# record. The EXTRN list is EMPTY, so this row needs no /alternatename and no
# forwarder; its src defines the flat C name the port already calls.
#
# THE SECOND READER WAS MEASURED BEFORE THE SEAT, which is what an arity-one row
# costs that the uniform rows did not. The same cell has TWO halves and TWO
# readers: this row reads the pair at cell+0 (the enter half) and
# port/unmatched/MirrorLuigi_Behavior.cpp -- still a host copy -- reads the pair
# at cell+8 (the tick half) as a plain cdecl (self, arg) call. They are
# DISJOINT records, so the enter word takes the __fastcall face and the tick
# word keeps the cdecl body it already has. Nothing compares a stored pair by
# value, so there is no by-value sentinel and no one-face-per-code-word
# constraint here.
#
# THE SEAT IS ON THE CELL, not on the source pairs, because port_ov55_bringup
# already runs __sinit_ov055_021118d4 and then port_mirrorluigi_state_seat in
# that order, and the seat already verifies all four mounted ROM words before it
# rewrites anything -- the MgCup shape, one file over. Only the ENTER word
# changes: it stops being the raw cdecl func_ov055_021112bc and becomes the
# __fastcall face the matched TU's own `call edx` needs.

# symbols.txt. Gate 3 of that lane derived an ov006 class's block from its

# that derivation generalises to any overlay
# (runs/link100/out/PMFB8/ovblock.py, PMFB7's clsblock.py with the ov006
# hard-coding removed). THREE OF THE SIX CLOSE AND ARE TAKEN. THREE DO NOT AND

#   row                    vtable      class code block        pairs  run
#   func_ov032_021121b4   02113824   021111a0..0211244c      10   0211377c..021137cc
#   func_ov100_02145550   02148188   021443f4..0214589c      15   021480d4..0214814c
#   func_ov100_021453d8   02148188   the same block, the same fifteen records
#
# ---- func_ov032_021121b4, BUBBA'S TICK DISPATCHER -------------------------
#
# ov032 holds three classes and dsd named only two of them; id 228 BUBBA is the
# unnamed one, so every symbol it owns is func_ov032_*. Its vtable is 0x02113824
# (hal/actor_classes_ov055.cpp's sibling file states the three-route
# attribution: the factory, the RTTI string 12daBakubaku_c, and the SpawnInfo
# record), 31 slots, EIGHT of which are its own ov032 bodies, and the
# first-to-last span of those snapped to symbol boundaries is
# 021111a0..0211244c. The sweep over it returns exactly TEN {code,0} pairs at
# 0211377c..021137c4, ONE SOLID RUN, ten distinct code words, and every
# reference into the run is one of __sinit_ov032_02112c10's own ten loads.
# Those ten are the five {enter, tick} pairs the sinit copies into the five
# sixteen-byte cells hal/actor_classes_ov032.cpp already seats and verifies.
# The universe CLOSES. (runs/link100/out/PMFB8/sweep_g2_ov032.txt)
#
# THE EMITTED SIDE, off the TU's own /FAsc listing under the port's own flags:
#     mov eax,[ecx+8] / test eax,eax / mov ecx,[ecx+12] / add ecx,esi /
#     call eax
# -- the member at offset 8 of the record, which is the tick half, receiver in
# ecx, ARITY ZERO, no push and no cleanup. So the five TICK words take zero-arg
# __fastcall faces. /Zp4 changes 0 listing lines outside the TITLE and is not
# claimed: the member sits at offset 8 of its holder, 0 mod 8.
#
# THE FIVE ENTER WORDS ARE NOT TOUCHED, and the reason is measured rather than
# assumed. Their dispatcher, src/func_ov032_02111ff4.cpp, is ALREADY in the link
# (port/slice_pmf2.txt) and its emitted transfer is `jmp edx`, a TAIL JUMP: the
# caller's own frame survives, so the cdecl body reads the caller's first stack
# word, which is `c` -- exactly self. That is lane PMFB7's reading of why the
# enter halves of its twenty-one rows stayed raw, reproduced here on this
# overlay (runs/link100/out/PMFB8/ctl_emit.json). It is also why MirrorLuigi's
# gate-1 row needs a face and this overlay's enter half does not: an extra
# argument stops MSVC tail-jumping, and a CALL does not carry the caller's
# frame.
#
# NOTHING COMPARES A STORED PAIR BY VALUE in this class. The three other readers
# of the field -- src/func_ov032_02111254.c, _02111350.c and _021113fc.cpp, and
# the row's own `!= data_ov032_02113aac` test -- all compare the CELL POINTER,
# not a function word, so there is no by-value sentinel and no
# one-face-per-code-word constraint.
#
# ---- func_ov100_021453d8 AND func_ov100_02145550, THE DOOR'S TWO HALVES ---
#
# daDoor_c's vtable is 0x02148188 (dsd's own, and inferred_stub_adjudicated.txt
# names it for slot 6), 34 slots, SEVEN of which are its own ov100 bodies, and
# the block is 021443f4..0214589c. The sweep returns exactly FIFTEEN {code,0}
# pairs at 021480d4..02148144, ONE SOLID RUN, fourteen distinct code words
# (0x02144730 is held twice), and every reference into the run is one of
# __sinit_ov100_02147698's own fifteen loads. That is precisely the set
# port/unmatched/Door_Behavior.cpp already enumerated by hand, derived this time
# from the class rather than read off a host file.
# (runs/link100/out/PMFB8/sweep_g2_ov100.txt)
#
# THE TWO ROWS ARE THE TWO HALVES OF ONE NODE. The sinit builds nine 0x10-byte
# nodes out of those fifteen statics plus arm9's data_02086b58, the NULL pair;
# 021453d8 seats the node at c+0x140 and dispatches the pair at node+0,
# 02145550 dispatches the pair at node+8 every frame. Both test word 0 against
# zero first, so the null node stays safe.
#
# BOTH ARE ARITY ONE and their emitted sides agree word for word:
#     021453d8   mov edx,[ecx] / test / mov ecx,[ecx+4] / push a2 /
#                add ecx,eax / call edx
#     02145550   mov edx,[ecx+8] / test / mov ecx,[ecx+12] / push eax /
#                add ecx,esi / call edx
# one pushed word neither caller pops, receiver in ecx. So ONE face shape serves
# both halves: __fastcall(self, dead_edx, void *arg), fourteen faces for

# on 021453d8 and _func_ov100_02145370 on 02145550, which is already in the link
# through port/slice_gate22.txt, so neither row needs an /alternatename.
#
# THE ARGUMENT COUNT OF THE BODIES IS THE ARM RIDE-THROUGH ALREADY RULED ON.
# Nine of the fifteen bodies take two words and six take one; Door_Behavior.cpp
# declares all fifteen as (void *, void *) because the caller cleans under
# __cdecl and r1 is set whether or not the callee reads it. The faces keep that
# ruling exactly: each face pops its own one stack word (that is what __fastcall
# does) and then calls its body cdecl with (self, arg).
#
# THE .text-BOUNDS REFUSAL THAT GOES AWAY WITH THE HOST COPY IS A STALE GUARD,
# and this is the one thing in this gate that had to be read out of history
# rather than measured. Door_Behavior.cpp says a non-code callback appeared in
# real play on 2026-08-07 and that the refusal stands "until that write is
# found". It was found in the SAME commit that added the refusal: 34285a74f
# ("port: the door ring's thiscall aliases were stack corruption - real faces")
# names the cause -- gate-22 aliases bound cdecl callers onto __thiscall bodies,
# so GoBehindPlayer's `ret 4` inside func_ov100_02144730 shifted the frame and
# its epilogue returned onto the door argument -- and fixed it with nine cdecl
# faces. The diagnostics were kept as diagnostics, not as a live shield. What
# survives the seat is stronger than what goes: port_door_callbacks_seat still
# verifies all fifteen mounted ROM words before it writes a single face, and

# ---- WHAT IS NOT TAKEN, AND THE MEASUREMENT THAT STOPS EACH ---------------
#
# func_ov002_020bd664 -- ITS UNIVERSE CLOSES; THE SEAT NEEDS A CALL SITE THIS
#   LANE DOES NOT OWN. This row is not a field row at all: it is a fourteen-slot
#   TABLE the src NAMES, `static PMF table[14] = { data_ov002_0210a14c, ... }`,
#   indexed by the kuppa script byte p[6]. So the universe is explicit rather
#   than swept, and it is closed: all fourteen read {code, 0} in the ov002

#   (runs/link100/out/PMFB8/sweep_g2_ov002.txt)
#   THE EMITTED SIDE is `mov ecx,[table+edx*8+4] / add ecx,self /
#   mov eax,[table+edx*8] / push a3 / push a2 / push p+7 / call eax` -- stride
#   eight, receiver in ecx, ARITY THREE, /Zp4 0 diff lines.
#   WHAT STOPS IT: hal/intro_kuppa_dispatch.cpp deliberately does NOT rewrite

#   `extern PMF` names, e.g. ?data_ov002_0210a14c@@3P8C@@AEXPAEHH@ZQ1@) and
#   drags in MSVC's magic-static guard (__Init_thread_header/footer/epoch,
#   __tls_index, __tls_array). Both are ordinary work; the call site is the
#   blocker.

# func_ov075_0211a194 and func_ov075_0211a26c -- THE RECORD SET IS NOT A
#   UNIVERSE. Both read a pair out of the OBJECT itself: 0211a194 copies six
