# run linkw wave 5 (lane w5-c): ov070's ENEMY PACK, per symbol.
#
# ov070 is an ACTOR overlay (base 0x0211f000, overlays.yaml; it shares that
# load window with ov071/ov073/ov074, the census's measured caution) carrying
# FOUR classes -- FlyGuy (232), Amp (266), FlameChomp (270) and FlameChompFire
# (271). Level 37 places Amp x2 and FlameChomp x1; FlameChompFire is spawned at
# run time by the chomp. FlyGuy's levels are unmounted, so its registry row is
# OFF (the ov019 rule: only rows for classes a bootable level spawns), but its
# sinit still runs and its data is still mounted -- see the PMF note below.
#
# This is the per-symbol mount (the gate-83/gate-50/gate-176 shape): the
# classes reach their SpawnInfo records, SharedFilePtr statics, dtor-chain
# nodes, state PMF arrays and file tables BY NAME. --pack keeps the runs at
# the ROM's own spacing.
#
# ==== WINDOW-ALIAS CHECK (the gate-199/202 rule) ============================
# The three registered SpawnInfo records were read as raw bytes out of
# extracted/overlays/overlay_0070.bin (base 0x0211f000; the probe rule --
# never the dsd export):
#   0x02123254 word[0]=0x021210ac Amp_Spawn             word[1]&0xffff=266
#   0x0212334c word[0]=0x02121af8 FlameChomp_Spawn      word[1]&0xffff=270
#   0x02123424 word[0]=0x021221fc FlameChompFire_Spawn  word[1]&0xffff=271
# Every spawn word lands inside ov070 itself and every id matches the arm9
# spawn-table slot it was reached from (0x02090864 + id*4). NO NAMING SHIFT in
# this overlay, checked class by class: each *_Spawn's literal pool stores the
# vtable adjacent to its own SpawnInfo, and every own slot of all four tables
# stays inside its own class's code -- 33 own slots measured, 28 in
# class-named TUs and 5 in address-named TUs of the same class, zero
# cross-class (delinks.txt, class by class). ov045's shift is ov045's, not
# a law of dsd.
#
# ==== FOUR SYMBOLS LEFT OUT =================================================
# The four vtables are HOST ARRAYS hal/actor_classes_ov070.cpp fills (the
# ov095/ov080 rule -- a mounted vtable hands a factory DS code addresses):
#   0x02123168..0x021231e4  _ZTV6FlyGuy         == _ZTV19daPropeller_Heyho_c
#                           (+ dsd splits data_ov070_02123184 / _021231a0)
#   0x02123278..0x021232f4  _ZTV3Amp            == _ZTV7daBrq_c
#   0x02123370..0x021233ec  _ZTV10FlameChomp    == _ZTV8daKrpa_c
#   0x02123448..0x021234c4  _ZTV14FlameChompFire == _ZTV8daKpFr_c
# All four are 31 slots (each span pinned by the next dsd symbol and by the
# reloc run ending at slot 30). _ZTV6FlyGuy is defined as zeroed host storage
# (FlyGuy_Spawn names it and the slice carries that TU's callers) but NOT
# filled -- the class is unregistered, so a fill would be dead words and a
# filled-looking table on a class the census must keep declining.
# The .init bodies and dsd's ".p__sinit_*" .ctor words stay out as always;
# all four __sinit_ov070_* are FUNCTIONS and all four link as slice TUs (the
# ov045 collision was swept for here: each sinit name is referenced by its own
# defining TU and nothing else, src-wide).
#
# ==== THE STATE PMFs HOLD DS CODE ADDRESSES (the Scuttlebug treatment) ======
# The four sinits copy 8-byte {fn, 0} source records out of .data into the
# live bss state arrays:
#   FlyGuy      12 sources 0x021230c0..0x0212311f -> six [2] arrays
#               0x0212358c/9c/ac/bc/cc/dc
#   Amp          6 sources 0x0212320c..0x0212323b -> data_ov070_02123668
#   FlameChomp   8 sources 0x021232f4..0x02123333 -> data_ov070_021236ac[8]
#   FlameChompFire 4 sources 0x021233ec..0x0212340b -> data_ov070_021236ec[4]
# Every source fn word relocates to an ov070 function that IS a matched src TU
# (relocs.txt, all 30 checked). The seat (ov70_seat_state_pmfs in
# hal/actor_classes_ov070.cpp) rewrites each source's fn word with its host
# body BEFORE the sinits copy -- the Scuttlebug/MontyMole/Crate recipe. All
# 30 are rewritten, FlyGuy's included: the ROM's arrays hold those bodies'
# DS addresses, the host arrays hold the same bodies' host addresses, and a
# future FlyGuy row then needs only a row and a fill.
#
# ==== SIZES =================================================================
# Everything below sizes correctly off the next-symbol delta except the LAST
# bss symbol: data_ov070_021236ec is FlameChompFire's 4-record state array
# (4 x 8 = 0x20, the sinit's own copy count), and the delta rule would give it
# the 4-byte floor. Pinned. bss runs to 0x02123720 (delinks.txt), so the pin
# stays inside the overlay's own span with 0x14 to spare.
