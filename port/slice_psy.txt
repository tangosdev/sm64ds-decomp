# ---- THE CLASS NAME COMES OUT OF THE ROM'S OWN type_info -------------------
#
# port/mg_fanout_costs.txt section 14's chain, which is stronger than a src
# spelling because a per-TU placeholder can be wrong and a relocation cannot.
# The word IMMEDIATELY BEFORE a class's vtable points at its type_info, and
# that record's second word is the name:
#
#     relocs.txt  from:0x0213c8c0 kind:load to:0x0213c7c8 module:overlay(6)
#     relocs.txt  from:0x0213c7cc kind:load to:0x0213c7d4 module:overlay(6)

# and 0x0213c7d4 reads "12dScMg3DEsp_c" in the overlay image. The type_info's
# THIRD word is the base's, from:0x0213c7d0 to:0x0213bc64, whose own name at
# 0x0213bd00 reads "19dScMgSingle3DBase_c" and whose base is ov004's
# 0x020bbf6c. So the hierarchy is stated by the ROM twice over before a line of
# code is read.
#
# ---- THE HIERARCHY IS THREE DEEP, AND THE CODE SAYS SO IN BOTH DIRECTIONS --
#
#     Scene -> dScMgBase_c         data_ov004_020bc0c0  36  (the framework's)
#           -> dScMgSingle3DBase_c data_ov006_0213e448  36  ovr 8, mark 6
#           -> dScMg3DEsp_c        data_ov006_0213c8c4  36  ovr 14, mark 12, nosrc 0
#
# port/mg_fanout_costs.txt section 3's row for 0x185 lists one vtable and says
# nothing about an intermediate base, which is the same gap run mg6 lane MEM
# found for 0x16b and section 13's CORRECTION 1 warns will fire again. It fires
# here. Both edges are read off code:
#
#   src/MgPsycheOut_Spawn.cpp (the factory) calls func_ov004_020b2adc(o),
#   writes data_ov006_0213e448 into o[0], constructs the Particle::SysTracker
#   at +0x471c, writes data_ov006_0213c8c4 over it, then constructs two Models
#   at +0x4f38 and +0x4f88, func_ov006_020e814c(+0x4fd8) and a
#   TextureTransformer at +0x51f4. Object size 0x5558.
#
#   src/func_ov006_020e76e4.c (slot 17, D0) unwinds them in the OPPOSITE order:
#   0x0213c8c4 first, the four sub-objects down, then 0x0213e448, then
#   Particle::SysTracker::~SysTracker(+0x471c), func_ov004_020b29c0 and
#   Memory::Deallocate. src/func_ov006_020e7660.cpp (slot 16, D2) does the same
#   without the Deallocate.
#
# So SIX of this class's fourteen overrides -- slots 2, 5, 7, 10, 26 and 33 --
# are the MIDDLE base's bodies, exactly the same six as 0x16b, and a seat that
# filled one derived table would leave six raw DS words in a table the factory
# installs.
#
# THIS IS THE THIRD CLASS UNDER THAT MIDDLE TABLE and hal/scene_mg_memory2.cpp
# section 3 predicted it: "If a THIRD class under this base is ever seated,
# promoting kSingle3DFaces to an exported seam ... is the right move." This
# lane does NOT take that move, and says why in hal/scene_mg_psycheout.cpp
# section 3 rather than leaving it implied: promoting the array means editing
# hal/scene_mg_flower.cpp and hal/scene_mg_memory2.cpp, which are two other
# lanes' files, in a fan-out where nine other lanes are cutting against the
# same base. The per-file copy is the shape both existing seats use, it is
# measured safe, and this row is appended after both of theirs so neither
# witness moves.
#
# ---- THE WIDTH IS 36, CHECKED FOUR WAYS ------------------------------------
#
# port/mg_fanout_costs.txt section 11 measured that twelve of twenty-nine
# widths in that file's own section 3 table were phantoms and that a 37-slot
# fill writes a host thunk over live ROM data belonging to another class. All
# three of its checks, plus a fourth this lane adds:
#
#   1. SPAN. config/arm9/overlays/ov006/symbols.txt puts the next symbol after
#      data_ov006_0213c8c4 at data_ov006_0213c954, exactly 0x90 = 36 words on,
#      so a 37th slot cannot exist inside the table.
#   2. TERMINAL SLOT. Slot 35 holds 0x020ad660, the word every dScMgBase_c-
#      derived table holds there.
#   3. WHAT THE WORD PAST IT IS. Index 36 reads 0x0000000a -- decimal ten, not
#      an address in any module -- and it is the FIRST WORD of the next config
#      symbol, data_ov006_0213c954, whose second word is 0x00000003.
#   4. RELOCATION COUNT. config/arm9/overlays/ov006/relocs.txt has exactly 36
#      relocations inside [0x0213c8c4, +36 words), and STILL 36 inside
#      [0x0213c8c4, +37 words). A vtable slot is a relocated code pointer; word
#      36 carries no relocation, so it cannot be one. Check 3 says what the
#      word is and check 4 says what it is not, from a different file.

# The middle table's own width was re-read the same way rather than cited from
