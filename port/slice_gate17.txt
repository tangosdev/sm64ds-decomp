# Gate 17: the LEVEL OVERLAY'S OWN ACTORS.
#
# ov009 has been mounted as data since gate 14 -- the object tables, the CLPS
# block, the paths, the entrances. This is the first time any of its CODE is
# compiled: four classes that exist only on the castle grounds.
#
# mwcc emits a class as [methods..., Spawn], so the block BEFORE a factory
# belongs to it, and each factory's own literal pool names the vtable it
# installs:
#
#   Bird_Spawn        0x02111a30  ->  _ZTV4Bird             = 0x02113958
#   CastleWater_Spawn 0x02111d8c  ->  _ZTV14daObjMcWater_c  = 0x02113a18
#   MetalNet_Spawn    0x02112048  ->  _ZTV8MetalNet         = 0x02113ae0
#   Flag_Spawn        0x021121f0  ->  _ZTV4Flag             = 0x02113ba0
#
# The ROM's own RTTI agrees from the other side: 0x02113ae0's class name is
# daObjMc_Metalnet_c and 0x02113ba0's is daMcFlag_c, and config carries both
# spellings for each table. Config used to attach these names one class late
# from Bird onward, so this gate was first written against func_ov009_* for
# the water and _ZN11CastleWater*/_ZN8DockPole* for the net and the flag;
# #1041 moved them onto the blocks they belong to.

# MSVC slot 5 is Virtual18, because MSVC spends one slot on the destructor
# where Itanium spends two. hal/cxxname_bridge.cpp already says so in as many
