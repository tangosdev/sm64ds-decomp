# Gate 19: the cannon in the moat wall.
#
# ov098's second actor overlay class set: CRATE, CANNON, WATER_BOMB and the
# two arrow signs. The castle grounds names one, and one only -- CANNON (207),
# the cannon behind the grate on the west moat wall.
#
# THE CONFIG'S NAMES ARE NOT SHIFTED IN ov098 either. All five factories
# install a vtable whose slot 0 is their own class's InitResources:
#
#   ArrowSignRight_Spawn -> _ZTV15daObjYajirusi_c   (both signs share it)
#   ArrowSignLeft_Spawn  -> _ZTV15daObjYajirusi_c
#   Crate_Spawn          -> _ZTV5Crate              RTTI daObjBlockS_c
#   Cannon_Spawn         -> _ZTV7daCnn_c            slot0 Cannon::InitResources
#   WaterBomb_Spawn      -> _ZTV7daWbm_c
#
# THE CANNON IS DORMANT AND THAT IS THE POINT. Its own Behavior reads the
# save's cannon-unlock bit before it will open; with a fresh save the lid
# stays shut, which is exactly what the level looks like before Bob-omb Buddy
# opens it. Nothing here chases the cannon-entry path.
src/Cannon_Spawn.c
src/_ZN6Cannon13InitResourcesEv.cpp
src/_ZN6CannonD0Ev.c
# _ZN6Cannon8BehaviorEv is NOT here either: it dispatches an mwcc
# pointer-to-member out of a four-entry state table, the gate-16 case for the
# fourth time. The dispatch frame and the state seat stay host
# (port/unmatched/Cannon_Behavior.cpp); the state bodies are matched src.
# State 1 (the lid opening) went byte-perfect at 2004/b56 in PR #1227:
src/func_ov098_0213ade8.c
src/_ZN6Cannon16CleanupResourcesEv.c
# _ZN6Cannon6RenderEv is NOT here: it dispatches Model slots 3 and 5 through
# a local shadow class, which is ROM numbering, and the host _ZTV5Model is
# MSVC's. Slot 5 the host array already serves both ways (the dual fill in
# hal/cxxname_bridge.cpp); slot 3 it cannot -- ROM 3 is UpdateVerts and MSVC 3
# is Virtual10, which takes a Matrix4x3 the shadow's declaration never passes.
# Host copy in port/unmatched/Cannon_Render.cpp.
#
# THE DESTRUCTORS ARE NOT HERE and slots 16/17 trap by name, the gate-17
# reading: nothing on the castle grounds destroys a cannon, and
# src/_ZN6CannonD1Ev.cpp is a real C++ destructor over its own shadow
# hierarchy -- MSVC would emit it under ??1Cannon@@UAE@XZ and synthesise
# member destructor calls against a layout that is not the ROM's.
