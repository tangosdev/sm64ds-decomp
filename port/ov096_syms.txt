# ==== THE CAST MAP, BOTH ATTRIBUTION ROUTES, AND THREE CONTESTED IDS =======
# Route 1: the arm9 spawn table word at 0x02090864 + id*4 is a RELOCATION, read
# out of config/arm9/relocs.txt, and it must land on this overlay's own
# SpawnInfo. Route 2: that record's own word[1] low halfword must equal the id

#   id   SpawnInfo   table slot   word[0] spawnFunc               idhalf module

# ==== THE ALIAS RACE: THREE CONTESTED ADDRESSES, ALL THREE SETTLED =========
# This is the lane's defining hazard (T6, the Coffin/Spindrift shape: a
# silently wrong-object binding that neither the byte gate nor the linkage
# count can see). dsd marks all three of this overlay's SpawnInfo rows
# `ambiguous`, every arm9 relocation above reads `module:overlays(6,96)`, and

# THE BUILD TODAY: port/ov006_syms.txt already hosts data_ov006_02137998,
# data_ov006_021379b4 and data_ov006_02137a6c, and ov006 hosts 338 symbols
# inside ov096's span in total. Each is settled by reading the RAW BYTES of
# both claimants, not by trusting a label.
#
#   0x02137998 (id 240)
#     ov096: 02136d60 005f00f0 10000002 001f4000 001f4000 01000000 01000000
#     ov006: 0213799c 81ec44f8 000011da 000c84f8 ffff11de 41f400f8 0000410d
#   0x021379b4 (id 241)

# Every ov096 word[0] is a real e92d4010 prologue inside ov096's own .text and

# NO BRIDGE AND NO /alternatename IS NEEDED FOR ANY OF THE THREE: the two

# their records by C NAME, never by DS address. The ov077/ov080 0x02127848
# ruling, applied to three live contests instead of one. The only aliases this
# lane does write are the two RTTI-spelling bridges below, which are a

# ==== POKEY_SEGMENT IS POKEY: ONE CLASS, TWO SPAWN ENTRY POINTS ============
# The ov030 UKIKI_THIEF/UKIKI_STAR (267/268) shape, and it is proved three
# ways rather than assumed from the shared name prefix:
#   * src/Pokey_Spawn.c and src/PokeySegment_Spawn.c are IDENTICAL apart from
#     their own names -- both allocate 944 bytes, call _ZN5ActorC2Ev, store
#     _ZTV5Pokey at p[0] and construct the same four members at the same four
#     offsets (Model 0xd4, ShadowModel 0x124, MovingCylinderClsn 0x14c,
#     WithMeshClsn 0x180);
#   * the ROM agrees without the sources: the relocations at 0x02136d5c
#     (PokeySegment_Spawn's pool) and 0x02136dac (Pokey_Spawn's pool) both read
#     `to:0x021379d8`, the one table;
#   * PokeySegment's OWN record's typeinfo word (0x021379d4) is 0x0213798c,
#     POKEY's __si_class_type_info, whose name string reads "9daSanbo_c".
# There is no _ZTV12PokeySegment anywhere in config, no PokeySegment method,
# and no second vtable. ONE fill serves both ids; the two registry rows differ
# only in their id and their factory.
#
# ==== THE TWO VTABLE WIDTHS, AND ROUTE B LIES ON TORNADO ===================
# Read slot by slot out of config/arm9/overlays/ov096/relocs.txt with every
# target resolved through config/arm9/symbols.txt (the ov072 method).
#
#   class    table       A reloc run  B next dsd sym  TRUTH  what pins it
#   Pokey    0x021379d8      31            31          31    semantic tail
#   Tornado  0x02137a90      31          36 LIES       31    tail + 5 zero words
#
# BOTH ARE 31 SLOTS, the plain Actor layout. The SEMANTIC TAIL pins both: slot
# 30 == 0x020100dc Actor::OnAimedAtWithEggReturnVec is the last Actor slot, and
# neither class is Platform-derived, so neither carries a 32nd. (Contrast
# ov092, the other half of this lane, which IS Platform-derived and closes on
# slot 31 = 0x020ee55c _ZN8Platform4KillEv.)
#
# ROUTE B LIES ON TORNADO. Its next dsd symbol is data_ov096_02137b20, the .bss
# start, giving 0x90 = 36 slots. Slots 31 through 35 (0x02137b0c..0x02137b1c)
# are ZERO in the raw image -- .data's tail padding up to .bss's align-32
# boundary, not five null virtuals. The reloc run stops at slot 30 for this
# table, which is the independent confirmation. The ov077 HeaveHo case with
# five pad words instead of three.
#
# THE FOURTH-SHAPE TRAP (a pointer-to-member SOURCE table read as more vtable)
# does NOT fire on either table, and the reason is the layout: ov096's TWELVE
# PMF source records sit at the very TOP of .data, 0x02137920..0x02137980,
# before either name string, so neither vtable has anything behind it but the
# next class's name string. The per-overlay .data layout is:
#     [12 PMF source pairs][Pokey name][Pokey typeinfo][Pokey_SpawnInfo]
#     [PokeySegment_SpawnInfo][_ZTV5Pokey][Tornado name][Tornado typeinfo]
#     [Tornado_SpawnInfo][_ZTV7Tornado]
#
# Own bodies per class:
#
#   slot  Pokey                        Tornado
#    0    Pokey::InitResources         Tornado::InitResources
#    3    Pokey::CleanupResources      Tornado::CleanupResources
#    6    Pokey::Behavior              Tornado::Behavior
#    9    Pokey::Render                Tornado::Render
#   12    Pokey::OnPendingDestroy      0x02043ac0  arm9 ActorBase default
#   16    PokeyD1                      TornadoD1
#   17    PokeyD0                      TornadoD0
#   18    func_ov096_021357a4          0x02010160  arm9 Actor default
#   19    func_ov096_02136cd0          0x02010154  arm9 Actor default
#   29    func_ov096_021357ac          0x02010124  arm9 Actor default
# Pokey takes the Lakitu/Spiny pattern (own 18, 19, 29 AND an own slot 12);
# Tornado takes the HeaveHo pattern (defaults at 18, 19, 29 and at 12). Every
# other slot is the shared Actor/ActorBase half, byte-identical between the two
# tables and to ov077's own shared half.

# ==== THE CLASS IDENTITY: TWO RTTI-SPELLING PAIRS, BOTH CONFIRMED =========
# Checked the way wave 1 requires -- each table's OWN vtable[-1] read through
# to its name string, AND both factory routes:
#   0x021379d4 -> 0x0213798c -> [0x0209a764 __si_class_type_info]

#                               and 0x02137a54 reads "7daTor_c"

# _ZTV7Tornado / _ZTV7daTor_c likewise. Every install route agrees:
#   _ZTV5Pokey    from 0x02135744 (D1 pool), 0x0213579c (D0 pool),
#                      0x02136d5c (PokeySegment_Spawn), 0x02136dac (Pokey_Spawn)
#   _ZTV7Tornado  from 0x02136df4 (D1 pool), 0x02136e4c (D0 pool),
#                      0x02137708 (Tornado_Spawn)

# The SOURCES split the two spellings: both factories spell the C++ name, both
# D0s spell the RTTI name. Two /alternatename bridges in the seat file cover

# ==== THE TWO VTABLES ARE EXCLUDED, AS HOST STORAGE ========================
# The ov015/ov016/ov017/ov022/ov045/ov080 rule -- a mounted vtable hands a
# factory DS code addresses. No dsd symbol falls inside either span, so no
# interior split has to be excluded with them:
#   0x021379d8..0x02137a54  240/241  31 slots  _ZTV5Pokey   / _ZTV9daSanbo_c

# ==== WHAT IS MOUNTED ======================================================

# omission. ov077 needed a `:0x60` pin because dsd's next-symbol delta for its

# rather than assumed: there is no phantom split in this overlay's bss.
