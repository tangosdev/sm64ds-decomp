# ---- 1. THE SCENE ID, DERIVED --------------------------------------------

# Everything below was read out of extracted/overlays/overlay_0005.bin at base

#                              Scene vptrs, |=1 and |=4 on the flag byte at

#                              data_ov005_020c24d8, is 0x48 = 18 words), the
#                              _ZTV5Scene shape -- NOT the 36-slot
#                              dScMgBase_c shape the ov006 minigames use.
#                              dScMiniGm_c is a direct Scene subclass; the
#                              minigames are not.

# ---- 6. THE PROOF, run mg15 lane MENU ------------------------------------

# Three headless runs of the same binary (walk_window.exe sha256

# the moment of use), all SM64DS_FAULTS_FATAL=1, all SM64DS_WINDOW_SELFTEST=1

#   SM64DS_SCENE=5 SM64DS_SCENE_FRAMES=150      rc 0, "clean", 0 UNHANDLED
#   SM64DS_SCENE=5 SM64DS_SCENE_FRAMES=300      rc 0, "clean", 0 UNHANDLED

# The stacked captures at 150 and 300 DIFFER on engine B
# (25dd00cc... vs b4b8d278...) and are IDENTICAL on engine A

# THE SLOT COUNTERS, from hal/scene_mg_menu.cpp's own witness:

#   no tap, 300 frames    init 1  clean 0  beh 299  render 300  pdes 0  d2 0

# The tapped run's Behavior STOPS at 240 -- forty frames after the f200 press
# plus the fade -- and CleanupResources, OnPendingDestroy and the D2 all fire
# exactly once. The scene tears itself down on a selection, which is what the
# ROM does.

# THE DECISION NUMBERS, named from the ROM (section 5 above) BEFORE the run:
#
#                       no tap        tapped at DS (88,60) on f200
#   data_0208a174        -1            3          the selected row
#   data_0209b2fc[0]      0            1          the launch latch

# the right game. data_02092664 is the load-bearing one: taking a touch and
# ASKING THE GAME FOR A SCENE are two different claims and only that word is
