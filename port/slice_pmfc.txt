# ---- THE STATED REASON IS DEAD ON EVERY ROW THAT COMPILES -----------------
#
# The census called the rows over a deliberately incomplete class "the
# genuinely hard half, because MSVC's unknown-inheritance form is four words".
# Measured on 148 objects that is false, and there is no split at all:
#
#   INCOMPLETE at the point of the ::* declaration   126 rows   8 bytes
#   COMPLETE                                          18 rows   8 bytes
#   open-coded as two ints, no ::* in the TU           9 rows   n/a
#
# Every compiled row reads the code word at +0 and the adjust word at +4 off
# one base and adds the adjust word into the receiver: [eax*8], [eax*8+4],
# `shl edx, 4` for a two-pointer Entry, `add ecx, <this>` at every site. The
# reason is the tree's global /vmg /vmm on the FLAGS line of every C++ edge in
# build/port/build.ninja. /vmg picks the general form for a class whose
# definition is not available; /vmm caps that form at multiple inheritance,
# which is exactly the ROM's eight bytes.
#
# Two host files still carry the pre-/vmg reading in their headers and are
# wrong about their own objects: unmatched/MgBase_StateDispatch.cpp ("MSVC's
# single inheritance member pointer is FOUR bytes") and
# unmatched/Bbh_PmfDispatch.c ("widens it to the 16-byte general form", which
# its own later note already corrects). Neither is load-bearing for anything on
# this slice, but a prose pass should fix both.
#
# ---- WHY "DELTA ZERO" IS THE WHOLE GATE, AND NOT A FORMALITY --------------
#
# The ROM's call through a member pointer, disassembled in three separate host
# files and re-confirmed here:
#
#     add   r3, r0, #8          ; &self->pmf
#     ldr   r1, [r3, #4]        ; the adjustment
#     add   r0, r0, r1, asr #1  ; this += adj >> 1   (ARITHMETIC SHIFT)
#     ands  r1, r1, #1          ; bit 0 of the adjustment is the VIRTUAL flag
#     ldrne r2, [r0]            ;   virtual: r2 = *this, the vtable
#     ldrne r1, [r2, r1]        ;            fn = vtable[code], a BYTE OFFSET
#     ldreq r1, [r3]            ;   direct:  fn = code, an address
#     blx   r1
#
# MSVC's eight-byte form adds the adjust word to `this` DIRECTLY: no asr #1, no
# virtual bit. The two agree on exactly one value, zero. So the delta-zero
# proof does two jobs and neither is optional: it makes MSVC's `add ecx, delta`
# equal to the ROM's `this += adj >> 1`, and it rules out the virtual path that
# no MSVC flag can express. A nonzero EVEN adjustment would be off by a factor
# of two; an ODD one is a virtual dispatch MSVC cannot spell.
#
# Sixteen source pairs were re-read out of the raw images for this slice
# (runs/link100/out/PMFC/deltas_static_pmfc.txt). A pair passes only when the
# image word at +0 is the target of a kind:load relocation in that module, the
# image word at +4 is exactly zero, no relocation is recorded from +4, and bit
# 0 of the code word is clear. All sixteen pass. Across the whole family this
# lane found NO adjust word with bit 0 set, so the VIRTUAL PMF class is empty.
#

# ---- THE 120 CALL-SHAPED ROWS, AND THE ONE FACE THEY ALL WANT ------------
#
# The dispatch is identical to the thirteen in every respect except position.
# Because it is not the last thing the function does, MSVC keeps the frame and
# emits `call <reg>` with ecx = this + adjust and NOTHING PUSHED. A tail jump
# hands the callee the caller's whole cdecl frame, so a seated
# void (*)(void *) body finds self at [esp+4]; a call hands it ecx and an empty
# argument area, so the same body reads whatever is on the stack. That is the
# entire difference between free and blocked for 120 rows.
#
# Measured over all 139 call sites in the family: 115 rows push zero stack
# arguments and clean nothing, 2 push one, 1 pushes two, 1 pushes three, and 1
# is the TAILJUMP+CALL row (_ZN6Player11ChangeStateERNS_5StateE, whose onExit
# half is a call and whose onEnter half is a tail jump).
#
# The face is a thunk the SEAT writes into the code word, not a rewrite of
# anything the ROM owns:
#
#     void __fastcall pmf_face_func_ovNNN_AAAAAAAA(void *self, void */*edx*/)
#     {
#         func_ovNNN_AAAAAAAA(self);      /* the matched cdecl body */
#     }
#
# __fastcall puts the first argument in ecx, exactly where a member-pointer
# `call <reg>` leaves the receiver; the second parameter absorbs edx, which the
# dispatch does not set. The thunk cleans no stack, matching the call site's
# absence of an `add esp`. Two properties make it a face rather than a metric
# trick: it changes no ROM data, and the TAIL-JUMP dispatchers reading the same
# table keep working through it, because a tail jump also leaves this + adjust
# in ecx. So one face can serve a table shared by a free row and a call-shaped
# row. The exact signature per row, extra parameters included, is the `face`
# column of runs/link100/out/PMFC/family_c.tsv.
#
# STANDING TRAP: a wrong-arity raw cast smashes the stack on first exercise.
# Every face's parameter count must come from that row's own listing in
# runs/link100/out/PMFC/listings/ and from nowhere else.
#
# The 120 rows sit in 79 host files and only 11 of them read a table that
# already has an installing seat, so for most of them the seat work above comes
# first and the face second. The largest single group is
# hal/cutscene_states_link100.cpp with 9.
#

# ---- ONE THING THE THIRTEEN STILL NEED, AND IT IS PURELY A NAME ----------
#
# Every one of the thirteen declares its table at namespace scope in C++ and
# NOT inside extern "C", so MSVC mangles the reference while the mount
# publishes the table under C linkage. Checked in the listings and against
# C:/tmp/l4seat/build/port/walk_window.map: all thirteen emit a mangled EXTRN,
# all seven tables are published as _data_ovNNN_XXXXXXXX, and NOT ONE of the
# seven aliases exists in the tree today. This is exactly the indexed-table
# family PMF3 answered in hal/pmf3_aliases.cpp, and the answer is the same
# shape. Without these seven the slice does not link, and the failure looks
# like an unresolved external rather than anything about member pointers.
#
#   #pragma comment(linker, "/alternatename:?data_ov002_021097bc@@3PAUEntry@@A=_data_ov002_021097bc")
#   #pragma comment(linker, "/alternatename:?data_ov002_0210af2c@@3PAUEntry@@A=_data_ov002_0210af2c")
#   #pragma comment(linker, "/alternatename:?data_ov014_0211476c@@3PAUEntry@@A=_data_ov014_0211476c")
#   #pragma comment(linker, "/alternatename:?data_ov034_02114538@@3PAUEntry@@A=_data_ov034_02114538")
#   #pragma comment(linker, "/alternatename:?data_ov063_0211efbc@@3PAUEntry@@A=_data_ov063_0211efbc")
#   #pragma comment(linker, "/alternatename:?data_ov071_02122ecc@@3PAUEntry@@A=_data_ov071_02122ecc")
#   #pragma comment(linker, "/alternatename:?data_ov085_0212fe88@@3PAUEntry@@A=_data_ov085_0212fe88")

# They pass alternatename_guard for PMF3's reason: the LHS is a C++-mangled

# RHS land in the map at one address, which is the guard's healthy shape. The

# (_data_ov071_02122ecc_d=_data_ov071_02122ecc, a second dsd spelling of the
# same storage, in hal/actor_classes_scuttlebug.cpp); that one aliases the C
# name to the C name and does not collide with this one.
