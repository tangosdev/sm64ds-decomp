# run link100 lane PMFB1: THE THIRTEEN FREE POINTER-TO-MEMBER DISPATCHERS,
# BUILT -- AND THE RECORD-STRIDE DEFECT THAT HAD TO BE FIXED FIRST.
#
# Lane PMFC2 measured the whole family (153 rows) and left a READY SLICE naming
# these thirteen as FREE: every one a tail jump, every one over a table whose
# adjustment words are proven zero and whose function words are rewritten with
# HOST addresses by a seat before the class can spawn. That reading is right
# about the dispatch and right about the seats. The full measurement is
# runs/link100/out/PMFC/family_c.tsv and runs/link100/out/PMFC/report.md.
#
# ---- WHAT PMFC2's MEASUREMENT MISSED, AND HOW IT WAS CAUGHT ----------------
#
# PMFC2's width detector read the SCALE of the indexed operand
# (?data...@@3PAUEntry@@A[eax*8+4]) and recorded "index stride 8". It never read
# the LEA that feeds that operand, and it never compared the product with the
# stride the ROM itself uses. The product is what matters:
#
#     lea  eax, DWORD PTR [eax+eax*2]                       ; eax = 3 * index
#     mov  ecx, DWORD PTR ?data_ov002_021097bc@@3PAUEntry@@A[eax*8+4]
#     mov  eax, DWORD PTR ?data_ov002_021097bc@@3PAUEntry@@A[eax*8]
#
# which is 24 * index, not 8. All thirteen ROM bodies were disassembled at their
# own addresses out of extracted/overlays/ for this lane
# (runs/link100/out/PMFB1/rom_strides.txt); eleven of them stride TWENTY:
#
#     mov  r1, #0x14
#     mla  r3, r2, r1, r3          ; &table[index], stride 0x14
#
# and only the two ov063 rows stride sixteen (add r3, r2, r1, lsl #4). So on
# eleven rows MSVC was walking the table 24 bytes at a time where the ROM walks
# it 20. Index 0 is correct either way; every other state reads the wrong
# record. Seating those eleven as they stood would have shipped a wrong
# dispatch, not a linkage win -- and it would have shipped quietly, because
# every one of these state machines starts in state 0.
#
# ---- WHY MSVC SIZES A 20-BYTE RECORD AT 24 --------------------------------
#
# Probed under the port's own flags (runs/link100/out/PMFB1/sizeof_probe.cpp):
#
#     sizeof(PMF)                   8       __alignof(PMF)                4
#     sizeof(struct { PMF p; })     8       __alignof(struct { PMF p; })  8
#     sizeof({PMF pmf; int x[3];}) 24       __alignof(same)               8
#
# The pointer-to-member ITSELF is the ROM's 8-byte {function, delta} pair with
# four-byte alignment, which is what /vmg /vmm bought (block R8) and what PMFC2
# reported correctly. But MSVC gives any CLASS THAT CONTAINS a pointer-to-member
# an alignment of eight, and that rounds a 20-byte record up to 24. The ROM's
# record is 20 and is not aligned to 8 at all.
#
# ---- THE FIX IS A COMPILE OPTION ON THE THIRTEEN, AND NOTHING ELSE --------
#
# /Zp4 caps the default structure packing of the TU at four, which is the
# alignment every field in these records actually has. It is the same lever, one
# step further, that block R8 already uses on this exact family: a per-source
# COMPILE_OPTIONS, no source edit, no ROM data touched, no reference the ROM
# does not make. It is applied to the thirteen TUs and to nothing else, in block
# R9d of port/CMakeLists.txt.
#
# Each TU has exactly two structures in it: the record, and
# struct C { char pad[N]; int idx; }, whose fields are all four-byte, so /Zp4 is
# a no-op on C and on the two ov063 rows (16 either way, kept on the option so
# the set reads as one).
#
# MEASURED, all thirteen, before and after
# (runs/link100/out/PMFB1/zp4_stride_table.txt and zp4_listings/):
#
#   row                    ROM stride   plain   /Zp4   form     EXTRN
#   func_ov002_020b9704        20         24      20   TAILJUMP unchanged
#   func_ov002_020b9750        20         24      20   TAILJUMP unchanged
#   func_ov002_020efa54        20         24      20   TAILJUMP unchanged
#   func_ov014_02111ebc        20         24      20   TAILJUMP unchanged
#   func_ov014_02111f08        20         24      20   TAILJUMP unchanged
#   func_ov034_021125b8        20         24      20   TAILJUMP unchanged
#   func_ov034_02112604        20         24      20   TAILJUMP unchanged
#   func_ov063_0211ddac        16         16      16   TAILJUMP unchanged
#   func_ov063_0211ddf4        16         16      16   TAILJUMP unchanged
#   func_ov071_021223c8        20         24      20   TAILJUMP unchanged
#   func_ov071_02122414        20         24      20   TAILJUMP unchanged
#   func_ov085_02129524        20         24      20   TAILJUMP unchanged
#   func_ov085_02129570        20         24      20   TAILJUMP unchanged
#
# and the object the option produces is the ROM's arithmetic instruction for
# instruction. The tick half of the Toad, for one:
#
#     lea  eax, DWORD PTR [eax+eax*4]                                   ; 5 * i
#     mov  ecx, DWORD PTR ?data_ov085_0212fe88@@3PAUEntry@@A[eax*4+12]  ; +12 adj
#     mov  eax, DWORD PTR ?data_ov085_0212fe88@@3PAUEntry@@A[eax*4+8]   ; +8  fn
#     add  ecx, edx                                                     ; +delta
#     pop  ebp
#     jmp  eax
#
# 20 * index + 8, the receiver adjusted, and a tail jump so the caller's own
# cdecl frame reaches the seated void (*)(void *) body at [esp+4].
#
# ---- WHY "DELTA ZERO" IS THE WHOLE GATE (PMFC2's reading, kept) -----------
#
# The ROM's call through a member pointer, at every one of the thirteen
# addresses above:
#
#     ldr   r1, [r3, #4]        ; the adjustment
#     add   r0, r0, r1, asr #1  ; this += adj >> 1   (ARITHMETIC SHIFT)
#     ands  r1, r1, #1          ; bit 0 is the VIRTUAL flag
#     ldrne r2, [r0] / ldrne r1, [r3] / ldrne r1, [r2, r1]
#     ldreq r1, [r3]
#     blx   r1
#
# MSVC's eight-byte form adds the adjustment to this DIRECTLY: no asr #1, no
# virtual bit. The two agree at exactly one value, zero. So the delta-zero proof
# does two jobs and neither is optional: it makes MSVC's add ecx, delta equal
# the ROM's this += adj >> 1, and it rules out the virtual path that no MSVC
# flag can express. Sixteen source pairs were re-read out of the raw images with
# their relocations by PMFC2 (runs/link100/out/PMFC/deltas_static_pmfc.txt); all
# sixteen carry a kind:load relocation on the function word, exactly zero in the
# adjustment word, no relocation from the adjustment word, and bit 0 clear.
#
# ---- WHAT EACH ROW RESTS ON ----------------------------------------------
#
#   data_ov002_021097bc   port_pushblock_states_seat aborts unless every record
#                         reads {the ROM's own address, 0}, then writes host.
#       func_ov002_020b9704   4 ROM referrers, all in linked TUs
#       func_ov002_020b9750   1 ROM referrer, linked
#
#   data_ov002_0210af2c   port_pathlift_states_seat, same abort, same fill.
#       func_ov002_020efa54   6 ROM referrers, all linked
#
#   data_ov014_0211476c   port_chain_chomp_states_seat aborts on a wrong
#                         function word or a nonzero adjustment over all twelve
#                         source pairs.
#       func_ov014_02111ebc   11 ROM referrers, all linked
#       func_ov014_02111f08    4 ROM referrers, all linked
#
#   data_ov034_02114538   port_wiggler_states_seat aborts unless enter and tick
#                         both read {rom, 0}.
#       func_ov034_021125b8   15 ROM referrers, 14 linked (the 15th is an ov052
#                             word at the shared load address; see the caveat)
#       func_ov034_02112604    1 ROM referrer, linked
#
#   data_ov063_0211efbc   bss. STATIC proof: ov063 0211ecd8 / 0211ece0 /
#                         0211ece8 / 0211ecf0, each {reloc'd code, 0x00000000}
#                         with no relocation on +4. ov63_bringup writes the host
#                         address into those four SOURCE pairs before the sinit
#                         copies them.
#       func_ov063_0211ddac   3 ROM referrers, all linked
#       func_ov063_0211ddf4   1 ROM referrer, linked
#
#   data_ov071_02122ecc   STATIC proof: ov071 02122e74 / 02122e7c / 02122e84 /
#                         02122e8c, each {reloc'd code, 0x00000000}.

#                         words after the sinit.
#       func_ov071_021223c8   2 ROM referrers, one linked (Coffin::Behavior)
#       func_ov071_02122414   2 ROM referrers, one linked (Coffin::Behavior)
#
#   data_ov085_0212fe88   port_toad_states_seat aborts unless each record reads
#                         {rom, 0}, then fills host.
#       func_ov085_02129524   3 ROM referrers, all linked
#       func_ov085_02129570   1 ROM referrer, Toad::Behavior, which has no
#                             matched TU; the reference reaches this row through
#                             the host body in unmatched/Ov085_Behaviors.cpp.
#
# THE REFERRER CAVEAT IS REAL. Referrers were found by ROM ADDRESS: relocs.txt
# plus an intra-module scan of the owning overlay for BL/B targets and for data
# words equal to the address. Overlays that share a load window therefore
# produce FALSE referrers, and two rows show one (.p__sinit_ov072_02122414 at
# the ov071 address, data_ov052_021125ac at the ov034 address). Neither changes
# a verdict, because both rows have a real linked caller in their own overlay.
#
# ---- THE SEVEN NAMES, AND WHERE THEY LIVE --------------------------------
#
# Every one of the thirteen declares its table at namespace scope in C++ and NOT
# inside extern "C", so MSVC mangles the reference while the mount publishes the
# table under C linkage. Read out of each TU's own /FAs listing: all thirteen
# emit a mangled EXTRN, all seven tables are published as _data_ovNNN_XXXXXXXX
# (each exactly once in walk_window.map, in an ovNNN_syms.c.obj), and not one of
# the seven aliases existed in the tree before this lane. They are in
# port/hal/pmfc_aliases.cpp, which carries the reading and the per-table seat.
#
# ---- WHAT COMES OUT OF WHICH HOST FILE -----------------------------------
#
# PMFC2's retire plan was right about six of seven files and wrong about two
# statics; both were caught by re-grepping the files rather than trusting the
# plan, which is what it asked for.
#
#   unmatched/Bbh_PmfDispatch.c            KEEP THE FILE.
#       removed func_ov063_0211ddac, func_ov063_0211ddf4, func_ov071_021223c8,
#       func_ov071_02122414 and the two externs that went dead with them.
#       KEPT _ZN12MansionSteps8BehaviorEv, which is CALL-shaped, and KEPT the
#       static bbh_pmf_call -- PMFC2's plan called it "now-unused", but

#   unmatched/ChainChomp_States.cpp        KEEP THE FILE.
#       removed func_ov014_02111ebc, func_ov014_02111f08 and the static
