# Gate 121: STATIC_ROCK (actor 61, ov102) -- Jolly Roger Bay's rocks.
#
# ---- what it is, and how the id was settled --------------------------------
#
# Level 8's census printed id 61 skipped, x33 -- the single biggest skipped
# class on the bay. Resolved the ROM's own way: ACTOR_SPAWN_TABLE entry [61]
# (arm9 0x02090864 + 61*4 = 0x02090958) is a load reloc to:0x0214e0e0
# module:overlay(102) -- g_profile_KI_IWA, whose +4 halfword reads 61. So
# the census id, the reloc target and the record's own id all agree.
#
# StaticRock is a Platform subclass. Its 800-byte object is built by
# daObjSimpleBg_c_classInit_KI_IWA (ov102 0x02148f8c), which installs vtable _ZTV13FortressTower
# (ov102 0x0214e1d8) -- the SAME table FORTRESS_TOWER (gate 102) and WARP_PIPE
# (id 298, gate 33) install. StaticRock defines no virtual methods of its own;
# it reuses that shared FortressTower/daObjSimpleBg_c body entirely.
#
# ---- everything but the factory is already in the link ---------------------
#
# Because _ZTV13FortressTower is the one table every ov102 daObjSimpleBg_c
# shares, and WARP_PIPE/FORTRESS_TOWER are already registered:
#   - all five methods (Init/Cleanup/Behavior/Render/D1) are already compiled
#     (gate 33's WARP_PIPE slice named them),
#   - the host vtable array _ZTV13FortressTower is already filled by
#     hal_fill_warp_pipe_vtable (hal/actor_classes_bob_world.cpp), and
#   - g_profile_KI_IWA is already mounted (ov102_syms.txt).
#
# So this gate's ONLY new symbol is the factory daObjSimpleBg_c_classInit_KI_IWA -- a distinct
# matched TU from daObjSimpleBg_c_classInit_BK_TOWER (same 0x0214e1d8 store, 800-byte object)
# -- plus the registry row, which reuses FORTRESS_TOWER's shared vtable fill
# (fill 0). No new overlay data, no PMF state table, no method face.
