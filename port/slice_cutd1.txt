# LANE CUTD1 (run link100, wave 5): the two cutscene models' COMPLETE-OBJECT
# destructors, the last two rows lane EXCEPT left behind when it gave
# _ZTV15TextureSequence[1] its thunk.
#
# THIS FILE ENROLLS NOTHING, AND THAT IS THE FINDING. Both matched TUs are
# already compiled -- port/slice_intro.txt lines 234 and 242 have carried them
# since run lvled -- and both objects sit in the port_slice_shared library
# today. What they were missing was a REFERENCE EDGE. The release link runs
# with /OPT:REF, so a compiled object nothing names is discarded before it
# reaches the map, which is exactly what happened to src/func_ov002_020f6870.cpp
# and what hal/model_dtor_seat.cpp's own header block already spells out for
# this family: "a matched TU added to a slice and referenced by nothing is
# discarded before it reaches the map ... the reference edge IS the work".
#
# A SECOND SLICE ROW WOULD HAVE BEEN A DEFECT, not a no-op: the same .cpp in
# two slices is the same symbol in two objects and the link fails on it. So
# this file is a RECORD in the shape of port/slice_except.txt's rows, and the
# edit that earns the count is four words in hal/actor_classes_intro.cpp.
#
# Both rows are verified BY ROM ADDRESS: the referrer is the ROM's own vtable
# word, read out of the raw overlay image at that overlay's own base and cross
# read against the relocation table, never out of a dsd copy.
#

#
# CORRECTION TO THIS LANE'S OWN BRIEF, recorded because a wrong address here
# would seat the deleting half in the complete half's slot. The brief said
# "EXCEPT says 020f69a8 for the first table's slot 0 and 020f6870 for the
# second". 020f69a8 is the Model's DELETING half and belongs at slot 1; the
# first table's slot 0 is 020f6a00, which is also what the brief's own opening
# sentence and the worklist's EXCEPT entry say. Both readings above agree with
# the opening sentence, and the two words were re-read before anything moved.
#
# WHAT UNBLOCKED BOTH ROWS. src/func_ov002_020f6870.cpp destroys the
# TextureSequence it owns through a hand-indexed vtable word,
#
#     p = *(void **)(c + 0x7c);
#     if (p != 0) (*(VFN)((*(int **)p)[1]))(p);        // ROM slot 1
#
# and _ZTV15TextureSequence[1] was a plain null here, so the body called
# address 0 (c0000005 on the opening cutscene, measured by lane SLOT5F).
# hal/model_dtor_seat.cpp seats that slot as of lane EXCEPT with the ROM's own
# body for it, _ZN15TextureSequenceD0Ev, behind a CDECL thunk. The convention
# is checked, not assumed: the VFN typedef above is a plain
# `void (*)(void *)`, which is cdecl under this compiler, and the thunk is
# `static void texseq_d0_cdecl(void *)`. Index 0 keeps its separate __fastcall
# thunk, which is the slot MSVC's own `delete p` reaches.
#
# AND THE FACES INTO THESE TWO SLOTS ARE __fastcall, NOT cdecl, which is the
# opposite convention and for a different reason: the reader decides. The one
# host caller into either table is
# src/_ZN14CutsceneObject16CleanupResourcesEv.cpp, which declares
# `struct Obj { virtual void v00(); virtual void m04(); }` and calls a->m04().
# That is an ordinary MSVC virtual call, so every code slot in these arrays is
# entered thiscall, matching the five neighbours already filled from
# _ZTV5Model / _ZTV9ModelAnim.
#
# WHAT RUNS DIFFERENTLY: NOTHING, and that is the point. The ROM calls slot 1
# here (CutsceneObject::CleanupResources throws the model away) and so does the
# host. Slot 0 is a slot the ROM fills and no live path dispatches, which is
# the house rule's "a vtable slot the ROM fills" and not a keep-alive. The
# risk that the D1 opens a new fault path is nil for a further reason: the
# ModelAnim's DELETING half, src/func_ov002_020f6778.cpp, carries the SAME
# hand-indexed TextureSequence call and has been seated at slot 1 and green
# since lane EXCEPT, so the D1 takes no path the D0 was not already taking.
#
# NO -D ROWS. Neither TU carries a placeholder macro; both are plain literal
# offsets with no compile-time configuration, so there is nothing to read out
# of their literal pools and nothing to define.
#
# NO CMAKE BLOCK either, for the same reason there is no source row: nothing
# new compiles.
