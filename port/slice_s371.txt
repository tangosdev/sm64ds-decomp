# ---- 3. THE WIDTH IS 37, AND HERE IS HOW EACH CHECK ANSWERS ----------------
#
# port/mg_fanout_costs.txt section 11's three checks are written to REFUSE a
# width. Every sibling in the family fails at least one of them at 37. This
# class passes all three, and the way each one reads is the point:
#
#   1. SPAN -- an UPPER bound only, so it can refuse a width and never grant
#      one. config/arm9/overlays/ov006/symbols.txt runs
#          data_ov006_0213b918   (the vtable)
#          data_ov006_0213b9ac   (the next symbol)
#      and 0x0213b9ac - 0x0213b918 = 0x94 = 37 words. For the twelve classes
#      section 11 corrected the same subtraction gave 36, which is what refused
#      them. Here it gives 37, so the check DECLINES TO REFUSE. That is all a
#      span can ever do and this file does not pretend it is more.
#
#   2. TERMINAL SLOT -- the check that actually decides. Every dScMgBase_c-
#      derived table holds ov004's 0x020ad660 at slot 35, because every one of
#      them INHERITS that body. This one does not: slot 35 is 0x020d1170, an
#      ov006 address inside this class's own code block. The base table
#      data_ov004_020bc0c0 holds 0x020ad660 at index 35 and this table holds
#      0x020d1170 there, so the slot is an OVERRIDE and the terminator argument
#      does not apply to it.
#
#   3. WHAT THE WORD IS -- and for this class the honest answer is that the word
#      is a RELOCATED CODE POINTER, which no phantom slot has ever been:
#          relocs.txt  from:0x0213b9a8 kind:load to:0x020d1188 module:overlay(6)
#      0x0213b9a8 is 0x0213b918 + 36*4. A slot-36 word that is live data
#      belonging to something else -- section 11's whole failure mode -- has no
#      load relocation of its own, because it is not a pointer. This one has
#      one, and 0x020d1188 is func_ov006_020d1188 in symbols.txt, sized 0x18,
#      immediately after func_ov006_020d1170.
#      The word at index 37, 0x0213b9ac, is the next config symbol, reads
#      0x00000100, and has NO relocation. The table ends exactly where the span
#      says it does.
#
# A FOURTH CHECK, WHICH IS THE ONE THAT WOULD HAVE SURVIVED ALONE. Slot 36 is
# DISPATCHED, twenty-five times over. A scan of the overlay image for
# `ldr Rd,[Rn,#0x90]` with Rn neither pc nor sp finds 26 sites, and 25 of them
# are inside this class's own code block:
#     func_ov006_020d122c 1, _020d1958 1, _020d1a3c 1, _020d27dc 3,
#     _020d36a4 3, _020d3ba0 6, _020d48dc 2, _020d4b7c 4, _020d5384 4
# The 26th, 0x020c1f5c in func_ov006_020c1f4c, is a FALSE POSITIVE of the
# offset scan and is recorded so nobody re-finds it: that body reads +0x8c,
# +0x90 and +0x94 as three consecutive OBJECT FIELDS and passes them to a
# formatter at 0x0203bf44. The Rn filter section 14 prescribes drops pc and sp;
# it does not know a field from a slot. The tell is whether the loaded word is
# then branched to.
#
# WHY THE CLASS NEEDED A 37th VIRTUAL AT ALL, in six instructions each. The
# family's slot 35 is a boolean over the spawn param's low byte, and this class
# needed to tell THREE values apart, so it split the boolean into two
# predicates and put the second in a new slot:
#
#   ov004 0x020ad660 (what every sibling inherits, 0x14, 5 instructions)
#       ldr r0,[r0,#8] / ands r0,r0,#0xff / movne r0,#1 / moveq r0,#0 / bx lr
#           -- return (field_8 & 0xff) != 0
#   ov006 0x020d1170 (THIS class's slot 35, 0x18, 6 instructions)
#       ldr r0,[r0,#8] / and r0,r0,#0xff / cmp r0,#1 /
#       moveq r0,#1 / movne r0,#0 / bx lr
#           -- return (field_8 & 0xff) == 1
#   ov006 0x020d1188 (THIS class's slot 36, 0x18, 6 instructions)
#       ldr r0,[r0,#8] / and r0,r0,#0xff / cmp r0,#2 /
#       moveq r0,#1 / movne r0,#0 / bx lr
#           -- return (field_8 & 0xff) == 2
#
# and field_8 is the low half of the spawn param, which section 17's third
# field is exactly. The two ov005 rows above carry low bytes 0x00 and 0x02, and
# 0x02 is the ONLY 0x02 in the whole 36-row table -- every other non-zero low
# byte in it is 0x01. So the class the family's width column was wrong about

# the two facts are the same fact.
