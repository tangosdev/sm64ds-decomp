0. WHY THIS EXISTS, AND WHY IT IS A RECOVERY
--------------------------------------------

There is one defect class the PC port keeps producing. It has three source
shapes and one mechanism: THE RECEIVER IS DELIVERED SOMEWHERE THE BODY DOES
NOT READ IT.

On ARM a C++ member's `this` rides r0, exactly like any other first argument,
so a ROM body transcribed into C takes it as an ordinary parameter. On x86
MSVC the same method compiled as C++ is __thiscall and takes it in ECX. Any
seam between those two worlds that does not name the receiver loses it, and
nothing warns:

  * an /alternatename directive whose two sides disagree (aliascheck)
  * a declaration that says (void) where the definition takes a receiver
    (aritycheck)
  * a vtable thunk whose emitted `ret` does not match the pop its slot demands
    (abicheck)

The class is not theoretical and it is not closed. It produced 11 of the 60
stored player crash reports as one family (blendmodelanim-setanim-abi-bridge),
and on 2026-08-16 alone it produced six separate receiver fixes on cons.

The checkers themselves are a RECOVERY. They were written 2026-08-10 on two
branches, port-abi-sweep (b472454c6, seven commits) and port-defect-wiring
(4ec689079, two commits), proven at the time, held pending a merge that
cleared on 2026-08-11, and then forgotten for six days while the class they
guard recurred six more times. Section 5 is the list of what had drifted.


1. WHAT EACH CHECKER ASSERTS
----------------------------

aliascheck.py -- no build required
  RULE R, receiver location. An /alternatename renames a symbol and says
  nothing about calling convention. Classify each side of every directive as
  taking its receiver in ECX (a non-static member declared __thiscall or
  __fastcall; the extern "C" @name@N spelling) or on the stack (everything
  else: a free function, a static member, a flat extern "C" name, a member
  declared __cdecl or __stdcall). ASSERT the two sides agree.
      DROPPED  stack left, ECX right. The caller pushes the receiver; the body
               reads ECX and gets whatever was in it.
      SHIFTED  ECX left, stack right. The caller sets ECX; the body reads its
               first stack slot, which holds the caller's first pushed
               argument or, if nothing was pushed, the return address. Every
               declared argument shifts by one on top of that.
  Decided from the decoration alone: no build, no demangler, no external tool.
  RULE R fires the moment a bad alias is written.

  RULE P, pop size. Both sides' callee-pop from their declared parameter
  lists. Needs `undname` to read an MSVC parameter list. WHEN undname IS
  ABSENT RULE P DOES NOT RUN AND SAYS SO. Rule R is complete without it.

  THIS RULE SPENT ITS FIRST DAY REPORTING "undname is not on PATH" ON A
  MACHINE WHERE undname WAS INSTALLED AND WORKING, and the first version of
  this document repeated that as an environment limit. It was not an
  environment limit, it was an invocation bug. undname takes FILENAMES:

      Usage: undname [flags] fname [fname...]
         or: undname [flags] file

  The helper piped the name list into its stdin, undname answered with that
  usage banner and exit 1, and the helper read the non-zero exit as "the tool
  is missing". Lane ABR1 caught it in review. Verified here afterwards, both
  directions, at
  ...\VC\Tools\MSVC\14.44.35207\bin\Hostx86\x86\undname.exe: the file form
  returns one bare demangled line per input line and exit 0; the stdin form
  returns the banner and exit 1. Demangling now lives in
  port/tools/msvc_undname.py, which finds undname on PATH or under the VS
  Build Tools layout, uses the file form, and has a selftest that pins both
  the known-good output and the fact that stdin is refused. Rule P runs.

  GATE: a receiver crossing that is not in port/tools/aliascheck_baseline.txt
  fails. Every baseline row carries an OPEN or INERT adjudication and an
  UNADJUDICATED row is reported as a defect of the baseline itself.

abicheck.py -- needs a build and dumpbin /disasm:nobytes
  A hosted virtual slot is entered as __thiscall: `this` in ECX, further
  arguments PUSHED, and the CALLEE pops them. A __fastcall thunk pops nothing
  unless it declares enough parameters to put the pushed ones on the stack,
  which is what makes the compiler emit `ret <n>`. ASSERT that for every
  vtable slot fill, the thunk's emitted `ret` equals 4 times the argument
  count its slot demands. Both halves are read from the emitted code: the slot
  from the fill's own store offset, the pop from the terminating ret.
      AUTHORITY  slot -> argument count from include/ActorBase.h (0..17) and
                 include/Actor.h (18..30).
      CONSENSUS  no header at all: a thunk whose pop disagrees with its peers
                 at the same slot index across every Actor table is suspect.
                 This is what covers the non-Actor tables and a slot whose
                 header authority is wrong.
  Two exemptions, both mechanical: a thunk whose every path funnels into
  port_actor_slot_decline / abort / RaiseException never reaches its own ret
  (DECLINE), and a table that is not the 31-slot Actor layout has a different
  slot map (NO_AUTHORITY, consensus only).
  GATE: exit 1 on any AUTHORITY mismatch or CONSENSUS outlier; exit 2 on a run
  that parsed ZERO slot fills, which is what plain /disasm produces.

aritycheck.py -- no build required
  The linker matches extern "C" symbols on the NAME alone, so a declaration
  and a definition can disagree about arity and nothing complains. ASSERT they
  agree.
      DROPS    the declaration has FEWER parameters. The callee reads a stack
               slot the caller never wrote.
      INVENTS  the declaration has MORE. Under __cdecl the caller cleans up,
               so the extra push is wasted rather than fatal.
  THE FULL CENSUS DOES NOT GATE. It reports 2075 disagreements on this tree
  (2105 when this section was first written; the difference is the
  else/return misparse fix of 2026-08-22, not tree movement) and an unknown
  but large fraction are parser artefacts; a gate at that number would be
  switched off within a day. Section 7 says what would have to change.
  TWO SUBSETS GATE:
    the RECEIVER SHAPE (--gate-receiver): a declaration with no parameters
    at all against a definition of an Itanium-mangled member (_ZN...) that
    takes at least one. 166 live rows are frozen in
    port/tools/aritycheck_receiver_baseline.txt and a NEW one fails the
    gate. That subset is exactly what PR #1539 and PR #1543 fixed on
    2026-08-16, and it is where the sixth live defect of section 6 surfaced
    once the reader learned the namespaced C++ declaration spelling.
    the PLAIN-NAME SHAPE (--gate-plainfunc, added 2026-08-22 after the Sort
    or 'Splode softlock shipped through the receiver gate's scoping): a
    PROTOTYPED declaration of a plain func_* symbol that drops, in a TU
    that CALLS the symbol (for a header declaration, in a TU that includes
    it), with every parameter on both sides provably one machine word.
    118 rows frozen in port/tools/aritycheck_plainfunc_baseline.txt; the
    rows that match the shape but fail the one-word proof (struct-by-value
    spellings, default arguments, variadic definitions) are HELD OUT and
    printed on every run, 15 today.

  TWO THINGS ARE HELD OUT OF THAT SUBSET, both decided from another checker's
  artefact rather than from a judgement made here, and both PRINTED on every
  run with the rows named. Added by lane RF1, 2026-08-17, because closing
  section 6 turned two of the subset's own rows into false statements.
      RIDE        a declaration inside a frame that tailjump_guard ASSERTS is
                  a tail JUMP to that same callee. A jmp reuses the caller's
                  cdecl frame, so the slot the callee reads is the slot the
                  caller wrote -- which is how the host reproduces `bx ip`
                  with r0 still live. Keyed on (declaring file, symbol)
                  against the guard's own `tu` and `callee`, and only the
                  HAND-DECLARED jump rows are consulted: the 22 derived veneer
                  rows need the extracted ROM and this checker must keep
                  running without one. Rows stay in the CENSUS; only the
                  ratchet subsets drop them. 8 rows today (7 when this was
                  written; the 8th arrived with mg8's merges, and five of
                  the 8 are plain-name rows the second ratchet also holds
                  out).
      NS BINDING  a namespaced C++ declaration only reaches the flat Itanium
                  definition through an /alternatename that binds its MSVC
                  decoration to that flat name. With no such directive the
                  callee is whatever defines the MSVC name, and comparing
                  arities against the flat body compares two unrelated
                  functions. 11 declarations tree-wide are unbound today.
  Neither is a judgement call this checker makes on its own, and both can be
  shown to STOP applying: abi_prove's prove_ride re-breaks the guard's table
  in a scratch copy and requires the two held rows to come straight back.

vtspan.py --sweep / --fills -- needs the extracted ROM, ALREADY ON CONS
  Not recovered by this lane; cons' own copy is used unchanged, and nothing in
  this change touches it. --sweep finds a host vtable array shorter than its
  ROM span; --fills finds a fill loop that leaves a ROM slot unwritten.
  run_checks fires both against ratchet files this lane wrote:
    vtspan_sweep_baseline.txt   EMPTY. Four tables were short when the wiring
        was written on 2026-08-10; the sizing lanes finished and cons measures
        0 short. --sweep therefore gates hard.
    vtspan_fills_baseline.txt   6 frozen fills (4 that leave slots unwritten,
        2 the scan cannot resolve to a ROM table at all). All pre-existing on
        cons. A gate that is red the day it lands is a gate somebody switches
        off, so these are frozen, counted on every run, and the list may only
        shrink. They are DEBT, not clearance -- nobody adjudicated them here.

run_checks.py -- the one command
  Fires the set and fails on any red AND on any vacuous pass. Its own
  contribution is stage 0: every checker's --selftest must pass before any of
  them is believed, because a regex that stopped matching a shape reports a
  clean tree in exactly the same words as a clean tree.

abi_prove.py -- the proof harness
  Section 3.

           from:0x02103254 kind:load to:0x020c3e4c module:overlay(7)

     and 0x020c3e4c is six instructions, all six of which matter because four
     of them are the argument setup:

         020c3e4c  ldr ip,[pc,#0xc]      ip = 0x020590fc
         020c3e50  mov r2,r0             arg 3 = the object
         020c3e54  mov r0,#0             arg 1 = 0, the table index
         020c3e58  mvn r1,#0             arg 2 = -1, "the current handle"
         020c3e5c  bx  ip
         020c3e60  .word 0x020590fc

     func_020590fc disables interrupts, takes table[0] and -- because arg 2 is
     negative -- reads the current handle out of its first word, indexes a run
     of 12-byte records by it, and then calls TWO list functions on the node at
     (obj - 0x20) before re-enabling. IT IS free().

     WHICH TWO LISTS, AND WHAT EACH CALL DOES. The first version of this
     paragraph said "unlinks the node from the two lists at +4 and +8" and that
     is half right and half backwards; lane RFR1's review disassembled both and
     only one of them is an unlink:

       rec+8   func_02059364(head, node)   a doubly-linked UNLINK. Patches
               node->next into node->prev->next and back, returns the new head.
               This is the node leaving the ALLOCATED list.
       rec+4   func_0205929c(head, node)   an INSERT, not an unlink. It walks
               the list while `node > cursor`, so the list is ADDRESS-SORTED,
               links the node in at that position, and then reads node[+8] as a
               SIZE and tests `node + size == next` to COALESCE with its
               neighbour. This is the node joining the FREE list.

     Together they are exactly free(): out of the allocated list, into the
     sorted free list, coalesced with the block above it. So the blast radius
     is worse than "spliced out of two lists". THE CALLER'S OWN RETURN ADDRESS
     WOULD HAVE BEEN INSERTED INTO THE FREE LIST AS A BLOCK HEADER, at
     (return address - 0x20), with its SIZE FIELD READ OUT OF CODE BYTES --
     whatever instruction happens to sit eight bytes into that header. The next
     allocation walks that list.

     on five sub-objects and then on the parent, and func_ov007_020b9770 calls
     it on two globals and NULLS EACH ONE on the next line. The "Player state"

    .githooks/pre-commit                       runs the no-build set
    .github/workflows/port-defect-checks.yml   runs two of them on every PR
    port/tools/install_hooks.sh                opts a clone into the hook
  These are POLICY, not tooling. They change contributor workflow on a public
  repository, and the port has nothing in CI at all today, so adding the first
  thing is a standing-gap decision rather than a wiring detail.

  ONE OF THEM IS NOT AS INERT AS IT LOOKS, AND THIS IS THE PART TO READ. The
  usual claim for a tracked hook is that it does nothing until somebody runs
  install_hooks.sh. THAT IS FALSE HERE. The sm64ds-decomp clone at
  the main checkout already has

      core.hooksPath = .githooks

  in its local config, shared by every worktree off it, and .githooks/ does
  not exist there yet -- which is the only reason nothing runs today. The
  moment that commit is checked out in that clone the hook is LIVE with no
  install step, on every commit touching port/, src/ or include/, at roughly
  a minute and a half a commit.

  It was live in this lane's worktree for exactly that reason, and it did
  work: the first commit on this branch ran the whole no-build set as a
  pre-commit and passed. That is a nice demonstration and it is still a
  workflow change nobody asked for. Turning it off afterwards is
  `git config --unset core.hooksPath`.

  The workflow file is genuinely inert until merged to a branch GitHub runs.
