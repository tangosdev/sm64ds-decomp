# gate 214 (run link100, lane BOOT): THE ROM'S OWN BOOT CHAIN
#
# 88 matched translation units that were unlinked for one reason only: the port
# booted through its own main() and never called the ROM's Entry/main chain, so
# nothing in the ROM's reference graph ever reached them. They are reached now,
# by the ROM's own calls, from the four spans hal/boot_os.cpp transcribes --
# src/func_02019780.c before the root heap, src/main.c's first three calls, and
# src/func_0201a054.c on either side of the game heap. Not one line in this
# file is kept alive by a call the ROM does not make.
#
# HOW IT WAS DERIVED, and how to re-derive it after a rebase. The --seed list
# is EXACTLY the set of ROM functions hal/boot_os.cpp calls and the --ban list
# is exactly the set it refuses, with boot_os.cpp's header naming what is
# missing for each. Everything else here is downstream of a seed through
# config/arm9/relocs.txt, which is the ROM's own reference graph:
#
#   python port/tools/boot_reach.py --root <root> --list <unlinked TU list> #     --ban  func_0205b858,func_0205bad8,func_02059e48,func_0206a88c,#            func_0205fde8,func_02019ebc,func_02058c84,func_02019780,#            func_02057198 #     --seed func_02057000,func_02059cb4,func_02059788,func_02059bc0,#            func_02059578,func_0201a03c,func_020427f8,func_02042784,#            func_02053a8c,func_0203d740,func_0201a4e4,func_0203bb5c,#            func_0203ad84,func_0203b684,func_020233f0,func_0201a5cc #     --out port/slice_gate214.txt slice
#
# func_02057198 is banned for a reason that is not about hardware: its matched
# TU declares func_0205a74c `static` and never defines it, which mwccarm
# accepted and MSVC refuses (C2129). hal/boot_hw.cpp carries the body with NO
# PORT_HOST_ABI tag, so it stays counted as work owed; the fix is one word in
# the decomp.
#
#
# TWO ROWS THE INPUT LIST WAS WRONG ABOUT, removed by hand after the first link
# said LNK2005 and the map said why:
#   src/func_020233f0.c   already seated by port/slice_gate29.txt, where it goes
#                         through hostgen and lands as host-src/src/
#                         func_020233f0.cpp -- a different source path to CMake,
#                         the same symbol to the linker. It was already LINKED.
#   src/UnloadOverlay.c   hal/scene_vs_menu.cpp defines UnloadOverlay through
#                         its VS_SEAM() macro, which is why a plain search for a
#                         definition does not find it. That face stays; the
#                         matched TU does not go in beside it.
#
#
# MEASURED AFTER THE LINK, and it is the most useful thing this file knows:
# 31 of these 88 land in walk_window.map and 57 do not, because the closure
# above is the ROM's RELOCATION graph and the linker walks the graph THE PORT
# ACTUALLY COMPILES. Every edge the ROM has that a host stand-in now owns is an
# edge the linker never sees, so everything behind it is unreferenced and
# /OPT:REF drops it. The three cut edges here, all of them host bodies that
# already existed:
#   LoadOverlay          hal/scene_boot.cpp   -> FS_LoadOverlay and the whole
#                                                card overlay/archive loader
#                                                (func_0205dc0c..func_0205e89c)
#   OS_SleepThread /     hal/os_thread.cpp    -> func_02057f54, the scheduler,
#   OS_WakeupThread                              and the lock family under it
#   nothing linked calls cstd::__assert       -> the MSL formatter chain
#                                                (func_0206bc8c..func_0206d940)
# They are left in the list rather than deleted: they cost a compile each, they
# are the ROM's own references, and the day one of those three host bodies is
# replaced by its matched TU they link with no further work. A reader counting
# rows here should count 31, not 88.
#
# NOT in here, on purpose: the 35 TUs a host file already defines (seating them
# is LNK2005 -- the CP15, context-switch and IRQ ones are PORT_HOST_ABI
# exceptions in hal/boot_hw.cpp, hal/cxx_aliases.cpp and ntr/runtime.cpp), and
# the hand-asm leaves MSVC cannot assemble, which hal/boot_hw.cpp stands in for
# with a tag apiece. hal/boot_globals.cpp hosts the DS globals these bodies
# read, sized by ROM span and carrying the ROM's own .data bytes.
