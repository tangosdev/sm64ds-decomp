# 2. THE WIDTH IS 36, CHECKED FOUR WAYS
# ===========================================================================
#
# port/mg_fanout_costs.txt section 11 measured that twelve of twenty-nine
# widths in its own table were phantoms, and that a 37-slot fill writes a host
# thunk over live ROM data belonging to another class. Both new tables went
# through all three of its checks plus the fourth that section 19 added:
#
#   1. SPAN. config/arm9/overlays/ov006/symbols.txt: data_ov006_0213e39c ->
#      data_ov006_0213e42c is 0x90 = 36 words, so a 37th slot cannot exist
#      inside the table. The span REFUSES 37. (For the middle table,
#      0x0213e448 -> 0x0213e4d8 is 0x90 = 36, the same reading four earlier
#      lanes made.)
#   2. TERMINAL SLOT. Slot 35 of both tables holds ov004's 0x020ad660, the
#      family terminator every dScMgBase_c-derived table carries unless it
#      overrides it (0x173 is the one exception in the family and it is a
#      different class).
#   3. WHAT THE WORD IS. Index 36 of the derived table reads 0x000000c2 and the
#      three words after it read 0xc4, 0xbf, 0xc0 -- a small-integer table, not
#      a code address. Index 36 of the middle table is 0x050a0a0f, the first
#      word of data_ov006_0213e4d8, which is the reading the flower lane made.
#   4. THE RELOCATION SET, which is the cheapest of the four and cannot be
#      fooled by a word that happens to look like a code address. Exactly 36
#      load relocations have a source in the half-open range 0x0213e39c up to
#      0x0213e42c -- first 0x0213e39c, last 0x0213e428 -- and there is NO
#      relocation row at 0x0213e42c. A vtable slot is a relocated word by
#      construction.
#
# THE BRACKET TRAP BIT THIS FILE WHILE IT WAS BEING WRITTEN, and the paragraph
# above is where it bit. The sentence originally spelled that range with a
# mathematical half-open bracket, one open square bracket and no close.
# port/CMakeLists.txt reads this file with CMake's file(STRINGS), which treats
# an unbalanced open square bracket as the start of a bracket argument: every
# line from there to the end of the file collapsed into ONE list element with
# the newlines turned into semicolons, so the loop that skips comment lines saw
# a single non-comment element that was not a path, appended nothing, and the
# build compiled the seat with an EMPTY SLICE. It failed loudly (twelve
# LNK2019s naming this class's own bodies) rather than quietly, which is luck
# rather than design. Run mg9 lanes S381 and S364 both recorded this trap; it
# is recorded here a third time because the failure it produces names the
# symbols and not the cause. KEEP SQUARE BRACKETS BALANCED IN A SLICE COMMENT.
#
# THE FIFTH CHECK (run mg9 lane LKY's relocation STRIDE) IS NOT QUOTED HERE.
# Section 11 recalibrated it as an upper bound that fails in the GRANTING
# direction, and it agrees with the span on this table anyway; a check that can
# only confirm adds nothing once four independent ones have answered.
#
# THE OVERRIDE AND MARKER COLUMNS RECONSTRUCT EXACTLY. Against dScMgBase_c's
# own table at 0x020bc0c0, this table differs at slots

# 5. THE POINTER-TO-MEMBER WALL IS ONE TU AND ITS UNIVERSE IS TWO
# ===========================================================================
#
# port/mg_fanout_costs.txt section 4 is explicit that neither a link nor a
# `::*` sweep licenses the word "none", so four detectors were run and the
# answer is not none.
#
#   - THE SOURCE, READ BEFORE THE FACE ARRAY WAS WIRED (section 14's practical
#     rule). Slot 6 (src/func_ov006_02109aac.c) is a plain
#     `switch (*(short *)(c + 0x53e6))` and slot 19 (src/func_ov006_021096c8.c)
#     is the ROM's own `cmp r0,#9 / addls pc,pc,r0,lsl #2` ten-arm jump table
#     on the same index. Neither is the wall.
#   - A `::*` SWEEP over all 41 TUs in the class's code block: EXACTLY ONE,
#     src/func_ov006_02107db8.cpp.
#   - THE WORD-DECODE SCAN, for the third shape neither prescribed detector can
#     see. Every word of 0x0210788c..0x0210a4ac was decoded looking for
#     `add Rd,Rn,Rm,asr #1`: ONE site, 0x02107e30, inside that same TU. Five
#     `blx Rn` sites exist in the block and all five are accounted for: two in
#     func_ov006_02107d80 and one in func_ov006_02107db8 are Model virtual
#     dispatches (section 6), 0x02107e44 is the member-pointer call itself, and
#     0x0210a3c4 is slot 0's tail dispatch of vtable slot 18.
#   - THE RELOCATION SET, which is a census rather than an absence and is one
#     grep. In the class's whole .data span exactly THREE data words carry a
#     relocation into its own code on top of the 36 vtable slots:
#
#         0x0213e2f0  -> 0x0210a400   the SpawnInfo's factory word
#         0x0213e2e8  -> 0x021082fc   an mwcc pair {code, 0}
#         0x0213e2f8  -> 0x02107ea8   an mwcc pair {code, 0}
#
# SO THE WHEEL'S STATE MACHINE IS TWO STATES AND THE UNIVERSE IS BOUNDED FROM
# THE CONSUMERS. data_ov006_0213e2e8 is installed by func_ov006_02108508, which
# vtable slot 18's func_ov006_02108524 calls; data_ov006_0213e2f8 by
# func_ov006_021082c4, which state 0x021082fc itself calls. Those two literal

# port/unmatched/MgRoulette_WheelDispatch.cpp.
#

# 6. TWO SHADOW-CLASS DEFECTS, BOTH ON THE WHEEL'S TWO MODELS
# ===========================================================================
#
# The wheel object at this+0x530c holds two HOST C++ Model objects at +0x10 and
# +0x60: MgMushroomRoulette_Spawn constructs them with _ZN5ModelC1Ev and vtable
# slot 0's func_ov006_021085c0 hands them NitroFS files 0x21d and 0x21e through

# CLASSES, which is the wrong half of port/mg_fanout_costs.txt section 13's
# test -- a shadow over a MOUNTED ROM table is correct because the port's fills
# keep ROM word order, a shadow over an MSVC vtable is not:
#
#   src/func_ov006_02107d80.cpp   ROM slot 5, byte +0x14, TWICE, with a NULL
#                                 scale. include/Model.h reads _ZTV5Model out
#                                 of the ROM as (0 D1, 1 D0, 2 DoSetFile,
#                                 3 UpdateVerts, 4 Virtual10, 5 Render), so
#                                 this is Model::Render(0). MSVC folds D1 and
#                                 D0, so the sixth MSVC word is one PAST Render
#                                 -- off the end of the vtable.
#                                 HOST COPY: MgRoulette_ModelRender_02107d80.cpp
#   src/func_ov006_02107db8.cpp   ROM slot 3, byte +0xc, once -- UpdateVerts.
#                                 The host's fourth word is Virtual10, which is
#                                 __thiscall with one stack parameter and so
#                                 returns `ret 4` off a stack the caller never
#                                 pushed. That is the exact pair of failures
#                                 MgMemory2_ShadowSlot_020c06dc.cpp measured.
#                                 HOST COPY: MgRoulette_WheelDispatch.cpp, which
#                                 also owns the member pointer above.
#
# WHICH CLASS THE OBJECTS ARE IS ESTABLISHED FROM THE CONSTRUCTOR rather than
# guessed from the call, which is the discipline that file records. Both
# dispatches stay VIRTUAL rather than qualified, for
# MgFlower_ModelRender_020c3bf4.cpp's reason.
