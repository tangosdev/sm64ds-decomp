# THESE ROWS NEED NO NEW INSTALLER AND NO NEW CALL SITE, and finding that out

# overlay's constructors so a seat can be called after them. It is already
# there: port_ov060_states_seat runs at hal/actor_classes_ov060.cpp:440, three

# THAT IS THE DEFECT THIS BATCH FIXES. A plain cdecl body in the cell is correct
# exactly while the dispatcher is a host copy calling it cdecl, which is what
# all four host copies did:
# `((void (*)(char *))(size_t)e->fn)(c + (e->adj >> 1))`. The matched TU emits

# read its argument off whatever the stack happened to hold. Each seated cell's
# host column therefore becomes a ZERO-ARGUMENT __fastcall FACE: sixteen cells,
# sixteen faces. The rows of those same seats that feed a table whose dispatcher
# is STILL a host copy keep their plain cdecl body.

#

# link named them, and the reason is worth more than the four counts were:

#   _ZN10BowserFire8BehaviorEv      (data_ov060_0211afb4,  8 slots)
#   _ZN14KnockDownPlank8BehaviorEv  (data_ov015_021149ec,  7 slots)
#   _ZN5Whomp8BehaviorEv            (data_ov079_02128280, 12 slots)
#   _ZN19BowserPuzzleManager8BehaviorEv (data_ov064_0211c904, 6 slots)
#

# stride 8 at the ROM body's own address with the pool word matching, [reg*8] on

# and a config span that covers exactly the filled cells. Nothing about the
# table stops them. What stops them is the DEFINITION FORM of the matched TU:
#
#   src/_ZN10BowserFire8BehaviorEv.cpp        defines `int BowserFire::Behavior()`
#   src/_ZN14KnockDownPlank8BehaviorEv.cpp    defines `int KnockDownPlank::Behavior()`

#   "int __fastcall bfire_behavior(void *,void *)"

# An /alternatename would NOT fix it: the flat name is called with the receiver
