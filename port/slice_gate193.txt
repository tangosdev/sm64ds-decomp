# GATE 193 EXTENSION (lane w3-d): SNOWMAN_HEAD (273) + SNOWMAN_BODY (274),
# the two ov072 classes gate 193 left unregistered. Both are plain 31-slot
# Actors whose vtables are 0x7c bytes and whose shared halves are BYTE-
# IDENTICAL to the two tables ov72_fill_shared already serves, so the fill is
# reused verbatim rather than re-derived. Full derivation in
# port/ov072_syms.txt's header; fills in hal/actor_classes_ov072.cpp.
#
# WHY THIS IS A REAL SEAT AND NOT A LINKAGE PADDING EXERCISE. Level 10's
# baseline census on this tip skips actor 0x111 -- that is SNOWMAN_HEAD, and
# daBgSnwmn_c::InitResources spawns it unconditionally until star 5 is
# collected. The class the port has been declining every Cool Cool Mountain
# boot is this one.
#
# BOTH RENDERS ARE SAFE AND STAY IN THE SLICE. Each dispatches slot 5 through
# a local six-virtual ROM-order shadow -- the same idiom that made
# _ZN11BabyPenguin6RenderEv a host copy -- but the receiver decides the
# outcome, and here it is a plain Model, not a ModelAnim. Both class
# destructors name the member type explicitly and both agree with the
# generated headers: SnowmanBody has Model m0 @0xd4 (0x50) / ShadowModel @0x124
# / MovingCylinderClsn @0x14c / WithMeshClsn @0x180; SnowmanHead has Model m0
# @0xd4 (0x50) / TextureSequence @0x124 / MovingCylinderClsn @0x138 /
# WithMeshClsn @0x16c. _ZTV5Model[5] is dual-filled and serves the shadow
# call correctly -- this is daBgSnwmn_c's case (whose Render is IN gate 193's
# own slice above), not BabyPenguin's.
#
# THE TWO D1s ARE NOT IN THIS LIST, for the MotherPenguin/OneUpLogo/
# BabyPenguin reason: each is a real MSVC-synthesised empty destructor over
# LOCAL shadow classes (Model/ShadowModel/TextureSequence/MovingCylinderClsn/
# WithMeshClsn declared with no bodies of their own), so MSVC emits calls to
# ??1Model@@QAE@XZ and friends that nothing in the link defines. Each chain is
# spelled directly in hal/actor_classes_ov072.cpp (smb_d1 / smh_d1),
# transcribed from the ROM listing at 0x0211f000 and 0x0211ff34 and
# cross-checked against the D0 bodies, which carry the identical member order
# and offsets. UNLIKE BabyPenguin's D1, both of these DO store their own
# table first (str r1,[r4] with the literal 0x021227c0 / 0x021228bc) -- that
# is in the host chains too, and it is a no-op re-store of the host array.
# Both stay byte-locked in src/ as the matched proof.
#
# ALL FOUR PMF DISPATCHERS ARE HOST COPIES, the BabyPenguin_StateEnter
# treatment, in port/unmatched/Snowman_StateDispatch.cpp:
#   func_ov072_0211fc78  SnowmanBody enter (pp+0)   pad 0x38c
#   func_ov072_0211fc3c  SnowmanBody tick  (pp+1)   pad 0x38c
#   func_ov072_0212059c  SnowmanHead enter (pp+0)   pad 0x328
#   func_ov072_02120560  SnowmanHead tick  (pp+1)   pad 0x328
# Each matched src declares `struct C; typedef void (C::*PMF)(); struct C {
# char pad[N]; PMF *pp; };` -- a REAL C++ pointer-to-member on a deliberately
# INCOMPLETE class. mwcc's PMF there is the ROM's own 8-byte {function,delta}
# pair; MSVC's representation for an incomplete class is the "unknown
# inheritance" form and calling through it does not reproduce those
# semantics. That is measured precedent on this very overlay, not caution:
# port/unmatched/BabyPenguin_StateEnter.cpp is the same call on the same
# six-cell shape and its header says exactly this.
#

# they cover only the two TICK dispatchers -- the two ENTER ones
# (func_ov072_0211fc78, func_ov072_0212059c) are not in the list at all. So
