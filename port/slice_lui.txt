# ---- 1. THE CLASS, RE-DERIVED FROM THE ROM --------------------------------
#
# The brief said "do not be confused by the class name" and the ROM agrees with
# it: 0x16e's spawn symbol is MgWanted_Spawn and the ROM's own RTTI string at
# 0x0213ce60 reads "12dScMgLuigi_c". Both names are right and the class name is
# the ROM's, exactly as port/mg_fanout_costs.txt section 2 records for curling.
#
# Everything below was read out of extracted/overlays/overlay_0006.bin at base
# 0x020bfec0 and out of config/arm9/overlays/ov006/, not out of the cost file:
#
#   SpawnInfo      0x0213ce0c  MgWanted_SpawnInfo, {factory, id twice}
#                  the doubled-id word 0x016e016e sits at 0x0213ce10 and the
#                  word before it is 0x020f3800, which is the factory
#   factory        0x020f3800  MgWanted_Spawn, 0x34 bytes
#   vtable         0x0213cf10  named by the factory's OWN load relocation,
#                  relocs.txt from:0x020f3830 kind:load to:0x0213cf10
#   width          36          all three of section 11's checks below
#   overrides      7           slots 0, 5, 6, 9, 16, 17, 18
#   markers        6           all six ruled REAL_DECOMP before seating
#   nosrc          0           among the override bodies
#
# THE WIDTH CHECKS, section 11's three, re-run rather than inherited:
#
#   1. SPAN     data_ov006_0213cf10 -> data_ov006_0213cfa0 is 144 bytes = 36
#               words. An UPPER bound only, and here it is exactly 36, so a
#               37th slot cannot exist inside the table.
#   2. TERMINAL slot 35 (0x0213cf9c) holds 0x020ad660, the word every
#               dScMgBase_c-derived table holds there. MATCH.
#   3. THE WORD index 36 (0x0213cfa0) is 0x2f474d2f, ASCII "/MG/" -- a file
#               path, which is curling's own control case. AND IT IS LIVE:
#               src/func_ov006_020f3460.c, slot 0, opens with
#               func_020adc74(&data_ov006_0213cfa0), so a 37-slot fill of this
#               class would write a host thunk over the first four bytes of
#               the path its own InitResources loads by name.
#
# ONE DERIVED TABLE, NOT THREE. dScMgCup_c (section 12) needed three because
# both its deleting destructors write an intermediate base's table. This
# class's two, func_ov006_020efc0c (slot 16) and func_ov006_020efc30 (slot 17),
# write data_ov006_0213cf10 and then call func_ov004_020b29c0 directly, so the
# chain is Scene -> dScMgBase_c -> dScMgLuigi_c with nothing in between and the
# fill has two tables to do, the base's and this one's.
#
# NO DISPLACEMENT RULING IS NEEDED FOR THIS CLASS, and that is worth saying
# because section 12 says the ruling "will be granted to whichever lane seats
# 361". src/MgWanted_Spawn.c calls `func_ov004_020b2adc(p)` WITH the pointer,
# where dScMgCup_c's factory calls it with none. Nothing in this lane rides an
# argument through into the base constructor.
#
# ---- 2. HOW THE LIST WAS DERIVED ------------------------------------------
#
# A relocation closure over config/arm9/{,overlays/ov00{1,4,6}/}relocs.txt with
# blocks joined through delinks.txt, from THIRTY-TWO roots: the factory, the
# class's own overlay constructor __sinit_ov006_02130f64, the seven vtable
# override bodies and the twenty-three state code words. That is MGA's root set
# rather than MG1's two, for a measured reason recorded here so the next lane
# does not repeat the first attempt: a two-root walk that also follows DATA
# symbol spans reached 251 ov004 functions, which is more than the whole
# family's union of 227 in section 4. A data symbol's span runs to the next
# config symbol and sweeps up relocations belonging to whatever sits after it.
# CODE EDGES ONLY, from explicit roots, is the walk that answers the question.
#
#     ov006  54 blocks   ov004  35   ov001  1   arm9 121
#
# THE arm9 HALF IS NOT LISTED, section 5's rule: all 121 already have matched
# TUs compiled into the build and come back through /OPT:REF the moment ov004
# or ov006 references them.
#
# WHAT IS ALREADY LINKED IS NOT LISTED EITHER, and the count is measured
# against this lane's own baseline map rather than assumed: 1 of the 54 ov006
# blocks, 29 of the 35 ov004 and the 1 ov001 are already objects in
# build/port/walk_window.map at 0fe9c7f62, because curling's slice and the
# framework seat brought them in.
#
# ---- 3. THE POINTER-TO-MEMBER WALL, THIS CLASS'S HALF ---------------------
#
# SIX ov006 TUs dispatch through an mwcc member pointer and every one of them
# is host-copied in port/unmatched/MgLuigi_StateDispatch.cpp. They are
# commented out below rather than deleted, with a pointer back there.
#
# A LINK NAMES AT MOST FIVE OF THE SIX, which is section 4's finding holding on
# a second class. func_ov006_020f300c declares its table INSIDE extern "C" --
# `extern "C" PMF data_ov006_02142254[];` -- so the global mangles as the plain
# C name the ov006 mount already defines and the linker is satisfied while the
# body strides an eight-byte ROM table by four. It was found by sweeping this
# slice for `::*`, which is the rule section 4 states and the only thing that
# finds it. The other five wrap the member pointer in a struct, so they mangle
# as @@3PAUEntry@@A -- the spelling tool finding 1 records that facegen does
# NOT refuse.
#
# TWO ov004 PMF TUs ARE IN THE CLOSURE AND ARE NOT LISTED, because the
# framework already owns both: src/func_ov004_020b3278.cpp is host-copied in
# port/unmatched/MgBase_StateDispatch.cpp and src/func_ov004_020b87e0.cpp is
# the state SETTER that stands as a named trap in hal/scene_mg_faces.cpp. This
# lane inherits both and adds neither.
#
# ---- 4. TWO ov006 BODIES IN THE CLOSURE HAVE NO SOURCE --------------------
#
# Neither has a delink block in config/arm9/overlays/ov006/delinks.txt and no
# src file defines either. The nosrc column in section 3's table is about the
# seven OVERRIDE bodies and is a correct zero; these two are closure holes, the
# same class of floor curling met six of.
#
#   func_ov006_020f15ac  A LIVE STATE. It is slot 7 of data_ov006_02142254,
#       the code word of the mwcc pair at 0x0213cd8c, and that load is the ONLY
#       relocation in the overlay that names it. port/tools/stategen.py reports
#       it under REFUSALS. So dScMgLuigi_c cannot reach one of its own
#       twenty-three states, and the address switch reports which state was
#       wanted rather than inventing a body. Curling's func_ov006_020e1854 was
#       this exact shape before lane CT1 transcribed it; this lane does NOT
#       transcribe, and says so.
#   func_ov006_020f2790  0x528 bytes, called eight times in a loop from
#       src/func_ov006_020f31dc.c (state slot 1 of data_ov006_02142234).
#       config/arm9/overlays/ov006/symbols.txt names it, which is why a
#       name-shaped check would have thought it decompiled. It stands as a
#       named trap in MgLuigi_StateDispatch.cpp, taking the one argument its
#       matched caller declares and passes.
#   NOTE src/func_ov002_020f2790.c EXISTS AND IS A DIFFERENT FUNCTION. ov002
#       and ov006 are not co-resident and both own bytes at that address. A
#       lookup by address alone would have seated ov002's body as ov006's.
#
# ONE ov004 HOLE IS ALREADY TRAPPED AND ONE IS NEW. func_ov004_020b2220 is one
# of the three ov004 addresses curling found with no source and
# hal/scene_mg_faces.cpp already carries its trap; this lane reaches it and
# adds nothing. func_ov004_020b0e84 (0x66c) is new, is named by ov004's
# symbols.txt and covered by no delink block, and is ON THIS CLASS'S RENDER
# PATH -- slot 9 calls func_ov004_020b1e34, whose whole body is a call to it.
# Its trap and the two arguments the host veneer loses on the way are in
# port/unmatched/MgLuigi_Faces.cpp section 4.
#
# AMENDED, run mg5 lane WTIMER. BOTH HOLES ARE CLOSED AND THE FIRST ONE WAS THE
# COUNTDOWN TIMER, so "this lane reaches it and adds nothing" was the sentence
# that hid the defect: reaching a trap 126 times in 300 frames is not nothing.
# func_ov004_020b2220 is the minigame HUD's scaled number drawer, and
# src/func_ov006_020f0e28.c hands it this class's countdown at (0x80, 0x28)
# every frame the HUD is up. It is host-copied in
# unmatched/MgHud_ScaledNumber.cpp. func_ov004_020b0e84 was seated by lane
# INTEG, and lane WTIMER closed the veneer's three dropped arguments as
# provably dead against the ROM listing (MgLuigi_Faces.cpp section 4a), so no
# veneer repair is owed.
#
# ---- 5. TWO DUPLICATE LINES, AND WHY THEY ARE HERE ------------------------
#
# src/func_ov004_020af5e0.c and src/func_ov004_020b0cac.c are also in

# ---- 6. ONE SHARED-HEADER PLACEHOLDER NAME MUST BE RENAMED ----------------
