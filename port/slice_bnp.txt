# ---- 10. WHAT THE ARITY AUDIT FOUND, AND WHAT IT DID NOT ------------------
#
# port/tools/aritycheck.py over this closure returns 31 rows. One is the real
# defect above. The rest were each checked against the ROM and none is owed a
# repair:
#
#   func_ov004_020af04c / func_ov004_020af27c declared 0-param by
#   src/func_ov006_020e6d8c.c and src/func_ov006_020e6d98.c. Both ROM bodies
#   ARE one-instruction tail jumps (`ldr ip,[pc]; bx ip`), so the port's
#   tail-jump mechanism carries the receiver and tailjump_guard asserts the
#   form. The seat's thunks pass the receiver into them.
#
#   func_ov006_020c4060, _020c7300, _020c7418 and _020e7110 are declared with a
#   parameter by their callers and DEFINED `(void)`. The ROM bodies genuinely
#   never read r0 -- checked one at a time -- so the definitions are right and
#   the extra argument is a harmless cdecl push the caller cleans.
#
#   func_ov004_020b1e34 is called with four arguments by
#   src/func_ov006_020ee034.c and defined with one. The ROM body is
#   `ldr ip,[pc,#4]; ldr r1,[r0,#0xb4]; bx ip` onto func_ov004_020b0e84, whose
#   prologue reads r0 and r1 and immediately overwrites r2, so the caller's
#   0xe0/0x14/1 are dead on the ROM as well. Ten sites in ov006 call this
#   veneer, including a body of an already-seated class, so it is exercised and
#   unchanged by this seat.
#
#   _ZN13SharedFilePtr7ReleaseEv declared `()` by src/func_ov006_020c6f3c.c is
#   a K&R-style declaration in a .c file, and the call DOES pass its argument.
#
#   The func_ov006_020c6f3c / _020c6f70 / _020c8a04 / _020c893c rows are
#   ADDRESS-TAKEN, not called: the factory hands them to func_020733a8 and the
#   destructors to __destroy_arr, both of which are host-defined and call the
#   pointer as a cdecl `void (*)(void *)`. This is the mg10 invisible-defect
#   shape and it was checked rather than assumed; none of the four is a
#   __thiscall thunk.
#
