# The ov091 data gate 32 needs for actor 27, the POST the CHAIN_CHOMP is
# chained to. ChainChomp::InitResources spawns it itself, so the chomp cannot
# run without it.
#
# The gate-18 shape (see ov085_syms.txt for the long version): an ACTOR overlay
# mounted PER SYMBOL with --pack, the overlay's WHOLE data span rather than a
# hand-picked subset, the vtables left out because they are host arrays the
# registry fills, and every *_SpawnInfo pinned to the record's real 0x1c.
#
# ONE VTABLE IS EXCLUDED BY ADDRESS, the ov100 treatment, and finding it took
# the ROM's own RTTI. Scanning this overlay's data for words whose +4 is
# Actor::BeforeInitResources (arm9 0x02011268) finds seven tables. Five carry a
# _ZTV* name and the generator's own rule drops them. Two do not:
#
#   _ZTV5Stump  RTTI 11daObjPile_c   <- ACTOR 27's OWN, and the
#                                                registry fills it: EXCLUDED
#   _ZTV11daDsnBase_c  RTTI 11daDsnBase_c   <- THWOMP's and GRINDEL's, and
#                                                neither is registered, so it
#                                                stays mounted as ordinary data
#                                                and nothing dispatches it
#
# THE CONFIG'S _ZTV5Stump IS NOT ACTOR 27's TABLE. g_profile_PILE (0x02135298,
# +4 halfword 27) names factory daObjPile_c_classInit at 0x02133938, and that factory's
# literal pool installs 0x021352bc, whose RTTI is daObjPile_c. The table config
# calls _ZTV5Stump lives at 0x021353ac, its RTTI is daHyuhyu_c, and it is
# FWOOSH's -- actor 231, daHyuhyu_c_classInit's own literal. So the six _ZN5Stump*
# bodies in src/ are Fwoosh's methods and actor 27's are the unnamed
# func_ov091_* block the table points at. Same shape as ov100's DOOR: the port
# compiles what the vtable points at and renames nothing.
