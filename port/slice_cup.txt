# ---- 2. THE THREE WIDTH CHECKS, RE-RUN ------------------------------------
#
#   1. SPAN. config/arm9/overlays/ov006/symbols.txt:
#        data_ov006_0213c154 -> next symbol data_ov006_0213c1e4 = 0x90 = 36
#        data_ov006_0213e448 -> next symbol data_ov006_0213e4d8 = 0x90 = 36

#   2. TERMINAL SLOT. Slot 35 holds 0x020ad660 on both tables, which every
#      dScMgBase_c-derived table holds.
#   3. WHAT THE WORD PAST THE END IS. On the middle table, 0x050a0a0f -- the
#      first word of data_ov006_0213e4d8, and the same reading
#      hal/scene_mg_memory2.cpp took. On THIS table it is 0x020e0a24 followed
#      by 0x00000000, an mwcc {code, adjustment} PAIR, and
#      src/__sinit_ov006_021304ac.c line 75 copies it:
#
#          data_ov006_02141930.p2 = data_ov006_0213c1e4;
#
#      That is CURLING's overlay constructor filling curling's state table
#      0x02141930 slot 2, whose address port/unmatched/MgCurling_StateDispatch
#      .cpp independently lists as 020e0a24. Re-read out of
#      extracted/overlays/overlay_0006.bin at base 0x020bfec0 and re-checked
#      against that sinit line by this lane rather than cited from section 11.
#      A 37-slot fill here corrupts the minigame that has shipped longest.

#   A PROPOSED FIFTH CHECK FAILS ON THIS CLASS, IN THE GRANTING DIRECTION.
#   Run mg9 lane LKY offered one that "needs no symbols and no judgment": the
#   vtable's relocation stride runs at 4 bytes for exactly the table width and
#   then jumps to 8. Read off config/arm9/overlays/ov006/relocs.txt:

#     dScMgFlower_c       0x02140140   36 consecutive 4-byte relocs   -> 36 ok

#     dScMgCup_c          0x0213c154   37, then a gap of 8            -> 37 WRONG

#   The run does not stop at the end of this table because the word past the
#   end IS ITSELF A RELOCATED CODE WORD at the next four-byte boundary --
#   0x0213c1e4 is the mwcc pair's code half -- so its relocation continues the

#         if (c->pmf) (c->*(c->pmf))();
