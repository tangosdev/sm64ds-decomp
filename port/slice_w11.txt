# Run linkw wave 11, lane w11: NINETEEN ids whose vtable is ALREADY a filled
# host array and whose overlay is ALREADY mounted. One TU each, and nothing
# else: no new mount, no new vtable, no new fill, no wrapper.
#
# ---- WHY NINETEEN AND NOT SIX -----------------------------------------------
#
# Wave 9 and wave 10 found this class of registration with a tool whose WORK set
# was the ~70 classes that appear in the mounted levels' skip censuses. That set
# is structurally blind to exactly the cheapest case: an id whose table is
# already filled and whose overlay is already mounted, but which no censused
# level happens to place. Wave 10 caught six of those by eye and said so.
#
# This lane widened the sweep from those 70 rows to ALL 512 spawn-table ids:
# resolve every id to (owner overlay, the table its own Spawn stores), group the
# 512 by that pair, and ask three questions per group. 374 of the 512 resolve to
# an (overlay, table) pair; they fall on 295 distinct tables, 43 of which carry
# two or more ids. Nineteen unregistered ids sit on a table a REGISTERED sibling
# already fills:
#
#   MNT     the owner overlay is mounted                    19/19
#   FILLED  the table is a host array in walk_window.map    19/19  (by name)
#   REC     the id's own SpawnInfo is already mounted       13/19
#
# The thirteen with REC cost one registry row and one factory TU. The six
# without cost one extra line in their overlay's syms file. Six of the nineteen
# carry instances on a mounted level today (11 instances in total); the other
# thirteen carry none, and are taken for the linkage and because the next lane
# that mounts a level placing them gets them for free.
#

# ---- EVERY REUSED FILL WAS CHECKED FOR A DONE-GUARD -------------------------
#
# Wave 10 hit this and paid for it: naming a sibling's fill on a second row
# CALLS IT TWICE, because port_actor_registry_install runs `if (k->fill)
# k->fill();` once per row. hal_fill_one_up_mushroom_vtable opens with
# port_one_up_mushroom_types_seat(), an UNGUARDED verify-then-rewrite over
# fourteen PMFs -- the second call finds the host bytes the first wrote and
# std::abort()s. So every fill named above was read to the bottom of its call
# graph before it was reused. Two kinds of evidence, and neither is an argument
# from naming:
#
#   ALREADY CALLED N TIMES IN THE SHIPPING BINARY -- idempotent by measurement,
#   because the tree on which this was measured boots 35 levels with the fill
#   running that many times:
#       hal_fill_sliding_platform_wf_vtable   4 rows (55, 138, 154, 155)
#       hal_fill_seesaw_bob_vtable            4 rows (39, 133, 149, 150)
#       hal_fill_goomba_vtable                2 rows (200, 202)
#       hal_fill_up_down_lift_hmc_vtable      2 rows (32, 33)
#
#   READ, for the six with a single existing caller. Each is a run of plain
#   `vt[n] = ...` stores plus a shared helper (bw_fill_shared / ac_fill_shared /
#   l7_fill_shared / kc182_fill_shared_0_30 / star31_fill_shared), which are
#   themselves nothing but stores. The four that reach a SEAT reach one that
#   carries `static int done; if (done) return;` at its top:
#       hal_fill_platform_vtable          done-guard (actor_classes.cpp)
#       port_enemy_death_states_seat      done-guard (unmatched/Enemy_UpdateDeath.cpp)
#       port_goomba_states_seat           done-guard (unmatched/BobOmbBuddy_States.cpp)
#       port_power_star_states_seat       done-guard (unmatched/PowerStar_States.cpp)
#   port_power_star_states_seat is the one that matters most: it carries the
#   SAME verify-then-abort as the mushroom seat, over the fourteen PowerStar
#   state PMFs, and it is safe only because of the guard three lines above it.
#
# No row here needs a 0 fill column. The one convention borrowed from wave 10 is
# the reason to check, not the workaround.
#
# ---- NO FACTORY WRAPPER, ANYWHERE -------------------------------------------
#
# The wrapper the wave-9 TILTING_PLATFORM_LLL row needed exists because that
# Spawn's final vptr store is the zeroed VT1 placeholder. None of these
# nineteen has that shape: each Spawn's own store is a load reloc onto a REAL
# dsd-named table (the ten listed above), so the registry can take the Spawn
# itself as the factory. Sizes 48..92 bytes, the plain Actor/Platform/Enemy
# constructor-then-store shape.
#
# ---- CLOSURE ----------------------------------------------------------------
#
# Every reloc inside every one of these nineteen Spawn bodies resolves to a
# symbol already in walk_window.map or already in the overlay's mount, except
# the table itself (a host array) and the Spawn's own name. That is why this
# slice is nineteen lines and no more: there is no closure to pull in.
