# Gate 42: the castle interior's PEACH_PAINTING (actor 38), ov010.
#
# The last id level 2's object tables left printing as skipped. A prior sweep
# marked it BLOCKED on ov052 and a RollingRock spawn; the ROM says otherwise.
# Both were the shared-base illusion: ov010 and ov052 are linked at the SAME
# base 0x021111a0 (only one overlay of a base loads at a time), so an address
# in one names a symbol in the other. dsd attributed two of PeachPainting's own
# internal references to ov052's names at the shared address:
#
#   * PeachPainting::InitResources' `data_ov052_02111e84(this)` is really an
#     arm_call to:0x02111e84 module:overlay(10) -- _ZN13PeachPainting20UpdateModelTransformEv, a
#     three-line helper that sets a rotation matrix and copies three scale
#     words. ov052's 0x02111e84 is a CLPS collision table (first word "CLPS");
#     calling it would crash. The real callee is the ov010 function, compiled
#     here.
#   * The `daGrock_c_classInit` the source hands Model::LoadFile is really an
#     ov010 load reloc to:0x02112d64 module:overlay(10) -- data_ov010_02112d64,
#     an 8-byte BSS SharedFilePtr the ov010 sinits construct, already mounted
#     in ov010_syms.txt. CleanupResources names the same data_ov010_02112d64
#     directly, which is the cross-check. No RollingRock is spawned; ov021's
#     RollingRock closure is not reached and is not built.
#
# So the class has NO cross-overlay dependency. Its SpawnInfo is already mounted
# (ov010_syms.txt, +4 halfword reads 38) and its methods are matched src. The
# two mislabeled references are closed by /alternatename in hal/actor_classes.cpp
# (data_ov052_02111e84 -> _ZN13PeachPainting20UpdateModelTransformEv, daGrock_c_classInit ->
# data_ov010_02112d64), which is the shared-base reading gate 40/41 already used
# for the same overlay.
