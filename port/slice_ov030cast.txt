# 3. THE FOUR DISPLACED TUs, EACH WITH ITS OWN REASON
# ===========================================================================
# The byte-matched original of each stays in src/ as the proof and is dropped
# from this list, because a host copy defines the same symbol and listing both
# would be an LNK2005.
#
#   src/func_ov030_02114170.cpp   -> unmatched/Ukiki_StateEnter.cpp
#   src/func_ov030_02114134.cpp   -> unmatched/Ukiki_StateTick.cpp
#     Both are mwcc POINTER-TO-MEMBER dispatch on a deliberately incomplete
#     class -- `struct C { char pad[0x3a4]; PMF *pp; };`, no base, no virtuals
#     -- so mwcc's PMF is the ROM's own 8-byte {function, delta} pair and MSVC's
#     "unknown inheritance" form is not a plain function pointer. This is the
#     BabyPenguin six-cell shape exactly (port/unmatched/BabyPenguin_StateEnter
#     .cpp and _StateTick.cpp), one cell wider: ELEVEN cells, each two pairs
#     (`S16 { S8 lo, hi; }` in the sinit's own declaration), enter at pp+0 and
#     tick at pp+1. src/func_ov030_021141a8.c is the cell-pointer installer --
#     it writes `*(Item16 **)(self + 0x3a4) = &data_ov030_02115e0c[idx]` -- and
#     it is UNCHANGED and stays in this slice.
#
#   src/_ZN13RollingLogTtm8BehaviorEv.cpp -> unmatched/Ukiki_Behavior.cpp
#     THE SHADOW-CLASS SLOT DEFECT, and it is the stack-unbalancing half rather
#     than the merely-wrong-body half. The matched src models the ModelAnim at
#     this+0xd4 with a local FOUR-virtual shadow `struct VObj` and calls `v3()`,
#     which is the ROM's own numbering: the fourth word of an Itanium model
#     vtable is UpdateVerts (0 D1, 1 D0, 2 DoSetFile, 3 UpdateVerts, 4
#     Virtual10, 5 Render). MSVC folds D1/D0 into one slot, so the host's fourth
#     word is Virtual10(Matrix4x3 &) -- __thiscall with ONE stack parameter,
#     returning `ret 4` off a stack this caller never pushed. That is the exact
#     pair of failures port/unmatched/MgMemory2_ShadowSlot_020c06dc.cpp
#     measured. WHICH CLASS THE OBJECT IS was established from the CONSTRUCTOR
#     and not guessed from the call: UkikiStar_Spawn / UkikiThief_Spawn both run
#     `_ZN9ModelAnimC1Ev(p + 0xd4)`, so +0xd4 is a ModelAnim, whose UpdateVerts
#     is MSVC slot 2 under include/ModelAnim.h. The dispatch stays VIRTUAL in
#     the host copy, for MgFlower_ModelRender_020c3bf4.cpp's reason.
#
#   src/_ZN13RollingLogTtmD1Ev.cpp -> spelled INLINE in the fill (slot 16)
#     A real MSVC-synthesised destructor over a local shadow class with no
#     vtable store of its own -- the MotherPenguin / OneUpLogo / BabyPenguin
#     shape, which gate 191 and gate 193 both keep OUT of the slice for the same
#     reason (MSVC mangles `RollingLogTtm::~RollingLogTtm` as
#     ?1RollingLogTtm@@UAE@XZ, never as the Itanium _ZN13RollingLogTtmD1Ev the
#     vtable slot needs). The chain is spelled directly in the thunk, HIGH
#     ADDRESS FIRST, from the src file's own member list.
#
# THE TWO SIBLING SHADOW CLASSES IN THIS SLICE ARE NOT DEFECTS, and the
# distinction is the whole rule -- a sweep that flags every shadow gets it
# wrong (MgMemory2_ShadowSlot_020c06dc.cpp's own closing paragraph):
#   src/func_ov030_02111350.cpp  (UkikiCage's Render, ROM slot 9) and
#   src/func_ov080_02127124.cpp  (RollingLogTtm's Render, ROM slot 9)
# both model a plain Model with a SIX-virtual shadow and call `m(0)`, index 5.
# hal/cxxname_bridge.cpp:511 DUAL-FILLS `_ZTV5Model[5] = mv_render` for exactly
# this, so index 5 on the host is Render too and the shadow's numbering is
# right. Verified by reading that line, not assumed. Neither object is a
# ModelAnim: func_ov030_021111a0.c (UkikiCage's D1) and the Maruta dtors both
# run `_ZN5ModelD1Ev(t + 0xd4)`, so both +0xd4 members are plain Models.
#
