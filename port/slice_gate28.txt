# Gate-28 slice: the MINIMAP, actor id 335 (0x14f).
#
# The other id the castle-grounds census printed as skipped, and the one the
# bottom screen is mostly made of. Twelve matched methods; what it needed was
# gate 27's eighteen-slot vtable law plus a registry row.
#
# Its SpawnInfo is ov002 0x0210c160, which config names _ZN7Minimap9spawnDataE,
# and like the HUD the ROM puts the CONSTRUCTOR in the record's +0 word
# (0x020fb8bc) rather than a separate Spawn veneer. The +4 halfword reads 0x14f
# and the +6 halfword 0x14f, which is the id and the two list priorities.
#
# ITS VTABLE IS THE SAME EIGHTEEN SLOTS as dMeter_c's, read out of ov002 the
# same way -- _ZTV7Minimap at 0x0210c1c0, and the ten shared slots are the
# byte-identical run ActorBase supplies for the HUD (0x02043c78, 0x02013ef4,
# 0x02043bac, 0x02043b2c, 0x02043afc, 0x02043af8, 0x02043ac8, 0x02043ac4,
# 0x0204357c, 0x0204349c, 0x02043494). Its own six are
#
#     0  020fb38c  Minimap::InitResources     12  020f9e94  OnPendingDestroy
#     3  020f9e8c  Minimap::CleanupResources  16  020f975c  ~Minimap (D1)
#     6  020fa690  Minimap::Behavior          17  020f978c  ~Minimap (D0)
#     9  020f9e98  Minimap::Render
#
# The vtable STORAGE the constructor installs is named _ZTV6dMap_c, not
# _ZTV7Minimap -- the ROM class is dMap_c and the two names sit on the same
# bytes. hal/sub_actors.cpp owns it, next to dMeter_c's.
#
# WHAT IT DRAWS. Minimap::InitResources writes BG3CNT_SUB (0x0400100e) itself,
# decompresses the level's map characters through G2S::GetBG3CharPtr and its
# tilemaps through G2S::GetBG3ScrPtr, and loads a BG EXTENDED palette through
# GXS::BeginLoadBGExtPltt / LoadBGExtPltt / EndLoadBGExtPltt -- which is why
# this waited on port/ntr/ppu_sub.cpp growing extended-palette support. It ends
# by ORing bit 3 into data_0209d454, the sub engine's layer-enable mask: the
# minimap is the thing that turns BG3 on, and hal/sub_screen.cpp has been
# publishing that mask into DISPCNT_B every frame with nothing setting the bit.
