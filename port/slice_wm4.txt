# Run link100, lane WM4, on top of lane WM3's rung W4.

# The plan is lane WMSCOUT's (runs/link100/out/WMSCOUT/report.md section 3, row
# W2, scored +3 against the pre-W4 map). Two of those three TUs are these; the
# third, src/func_02062734.c, is already in the link under port/slice_wm3.txt,
# so this rung's own arithmetic is +2 and the report says so rather than
# quoting the scout's number.
#
# WHAT IT RETIRES. hal/comms_seam.cpp's func_0204068c host face, which asked
# the transport for a peer's block directly. From here the game reads a peer
# through the cartridge's own two-step unpacker instead: func_0204068c hands
# data_020a0f74 and data_020a0f80 to func_02062778, which refuses an aid whose
# bit is clear in the receive buffer's liveness mask at +2 and otherwise steps
# func_02062734's packed offset -- one stride per set bit of the packing mask
# at +0 below that aid, the stride being the ROM's own halfword at
# data_020a0f74 + 0x410.
#
# WHAT ANSWERS IT. hal/wm_arm7.cpp's port_wm_publish_mp_recv, called from the
# remaining exchange face the moment the carrier completes a round. It writes
# the two masks and the packed blocks and nothing else; the stride is READ back
# from the ROM's own field and a disagreement with the carrier's block size is
# a hard fault rather than a silent walk.
#
# THE ONE DEVIATION, MEASURED. The cartridge allocates this buffer at 0x100
# (src/func_020408b0.c:41) for a four-player session (src/func_0203fa50.c:7
# passes mask 0xf), which is a ceiling of seven slots. This port hosts sixteen.
# A session that does not fit is published into hal/wm_arm7.cpp's own buffer
# under hal/vs_width.h's standing ruling, and at four and below the ROM's own
# allocation is what gets written.
