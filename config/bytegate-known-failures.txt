# Modelled on config/layout-known-issues.txt and config/rombuild-exclude.txt: the debt
# already in the tree is written down instead of silently allowed. This list should
# only ever shrink.
#
# WHY A LIST AND NOT A LIVE CHECK
# --------------------------------
# The other half of the byte-gate-failure class -- a zero-size record sharing an address
# with a sized function -- IS derived live, in chaos_db_ci.alias_collision_addresses(),
# because it reads nothing but committed config. This half cannot be: deciding it means
# running mwccarm, and the two workflows that regenerate chaos-db.json (update-chaos-data
# and report) run on a stock ubuntu runner with `pip install pyelftools capstone` and
# nothing else. tools/mwccarm and tools/bin are gitignored and no workflow fetches them,
# so there is no compiler in the process that computes the published count.
#
# THE HASH IS WHAT MAKES THIS SELF-HEALING
# -----------------------------------------
# Each row pins the sha256 (first 16 hex) of the source as it stood when the failure was
# recorded. The exclusion applies ONLY while the file still hashes to that value, so
# fixing one of these files restores its matched status with no edit to this list and no
# compiler in CI. Editing a file without fixing it is the case a bare name list would get
# wrong in silence; here the row goes stale and tools/test_bytegate.py fails on it, which
# is a loud request to re-run the gate rather than a quietly wrong number.
#
# The hash is taken over the file with CRLF folded to LF. There is no `text=auto` rule in
# .gitattributes, so a Windows clone materialises these files CRLF and the ubuntu runner
# that publishes the count materialises them LF. A raw-byte pin would miss on all 18 rows
# in CI, lapse every exclusion at once, and quietly restore the pre-policy number while
# every local check still passed. Do not re-pin these by hand; use --recheck.
#
# Format:  <sha256-16> <repo-relative src path> <reason>
# Lines starting with '#' are comments.
#
# TO ADD OR RETIRE A ROW
#   python tools/bytegate.py --recheck        # needs tools/mwccarm; prints the true set
#
# Re-derived at a6dd3d3ec: 18 rows, every one of them failing under all 12 versions.
# linkcheck reports all 18 as NO-SYM, and reports WRONG for none of them -- these are
# "counted without evidence", NOT "proven wrong". See audit/enrollment_report.md 4a.
