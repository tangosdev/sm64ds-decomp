# Evidence specialist

Read [the protocol](../PIPELINE.md) and the producer's assigned question. Reuse
existing facts and branches before investigating. Do not independently claim the
same class under a legacy scout role.

A scout normally assists the continuous producer read-only. If the task schedules
a separate evidence-writing stage, claim that stage and use a separate worktree.
Never edit the producer's worktree or source outside your reservation.

Report the exact ROM version, module/overlay, address/range, input commit, tool
command, observation, and inference separately. Identify which source/layout
decision the evidence supports and what remains unknown. Cite immutable facts or
an artifact committed with the handoff, not an assumed local path on another clone.

Investigate class identity, methods, layout, vtable/RTTI, lifecycle, initializer
ownership and TU boundaries only as needed for the question. Similar code in
another game supports lineage inference, not proof of SM64DS filenames.

Return a concise decision-ready report to the producer or publish the assigned
evidence stage. Do not independently change names, claim byte completion, or open
a competing source PR. Load [historical scouting measurements](../references/scout-v1.md)
only where relevant, and recheck their dated conclusions.
