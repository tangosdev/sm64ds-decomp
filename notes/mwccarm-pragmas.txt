# mwccarm recognised #pragma names (246 verified)
#
# WHY THIS FILE EXISTS: mwccarm SILENTLY ACCEPTS an unknown #pragma. A typo'd or invented
# pragma name compiles clean and leaves codegen untouched, which is indistinguishable from a
# genuinely inert lever. Sweeps have banked "pragma X is inert" for pragmas the compiler never
# honoured. See notes/mwccarm-codegen.md 6as.
#
# HOW THIS WAS DERIVED (2026-07-31, reproducible): pull every lowercase identifier out of
# tools/mwccarm/1.2/sp2p3/mwccarm.exe, then compile each one as `#pragma <name> off` with
# `-w illpragmas`, which prints "<file>:<line>: warning: illegal #pragma" for names the
# compiler does not know. A name is listed here only if it was verified INDIVIDUALLY --
# batching is unsafe because `#pragma warning off` suppresses the diagnostics for every line
# after it and inflates the accepted set.
#
# CAVEAT: 2004/b56 does NOT support -w illpragmas and stays silent on a bogus pragma. Screen
# against the 1.2 line (match.py --all does this for you).
#
# CORRECTIONS THIS LIST ALREADY PRODUCED:
#   generateconditionalassignments -> the real name is opt_generateconditionalassignments;
#                                     the recorded "inert" result never applied the pragma
#   scheduling                     -> NOT a pragma (the real control is the -opt schedule
#                                     COMMAND-LINE flag); "#pragma scheduling off is inert"
#                                     results are meaningless
#   long_calls                     -> NOT a pragma; src/unnamed/ov065/0211/func_ov065_0211aacc.c credited it for
#                                     a tail-call shape it does not produce
#
# Presence here means the compiler PARSES the name, not that the pragma moves codegen on your
# function. Proving a real pragma inert is still evidence; proving a fake one inert is not.
